# Синтетический корпус v1

Корпус полностью создан для ArticleFlow; он не содержит настоящих научных статей и не заменяет утраченный корпус EPOC/AAMS/USS. Все заголовки и абзацы отмечены как синтетические. В публичном Git находятся [генератор](../../scripts/build_synthetic_corpus.py) и [manifest.json](manifest.json) с SHA-256 каждого ожидаемого файла. Сами DOCX создаются локально: автоматическая проверка отклонила публикацию одного из них в открытом репозитории.

| Папка | Назначение |
| --- | --- |
| [train/](train/) | По два правильно оформленных эталона для каждого из трёх профилей |
| [evaluation/](evaluation/) | По два новых правильно оформленных документа для каждого профиля; не использовать при подготовке правил |
| [inputs/](inputs/) | Шесть тех же новых статей с переставленными частями аннотации и нейтральным оформлением; ещё один вход с отсутствующими авторами и практической значимостью |

Итого 19 DOCX: 6 train, 6 evaluation, 6 парных inputs и 1 missing-case. Каждый документ содержит таблицу, изображение с подписью, формулу OMML, внешнюю гиперссылку, жирное и курсивное выделения, верхний индекс и одноимённый постановке заголовок основной части. Профили `north`, `east`, `south` различаются семействами шрифтов, размерами, заголовками аннотации, интервалами, отступами и выравниванием. Входные документы содержат редакционную строку, которую нельзя принимать за авторов.

Список train/evaluation фиксирован в manifest до следующего исследования. Поскольку обе части выпущены одним генератором, это проверка структуры и сохранности при новых текстах, **не независимый перенос на реальные конференции**. Gold и input не должны передаваться модели одновременно. Метрики на этом корпусе нельзя складывать с 34 настоящими DOCX из прежнего локального исследования 011.

```bash
cp datasets/synthetic-v1/manifest.json /tmp/articleflow-synthetic-v1-manifest.json
python scripts/build_synthetic_corpus.py
cmp /tmp/articleflow-synthetic-v1-manifest.json datasets/synthetic-v1/manifest.json
python scripts/build_synthetic_corpus.py --verify
```

Первая команда сохраняет утверждённый manifest, генератор создаёт 19 DOCX, а `cmp` подтверждает, что их хеши совпадают с версией из Git. `--verify` дополнительно проверяет ZIP и основные сложные OOXML-элементы. PNG и ZIP теперь записываются канонически без платформенного сжатия; один manifest получен на macOS Python 3.11/3.14 и на Ubuntu сервера. Версии `python-docx` и `lxml` закреплены в CI. При осознанном изменении набора выпускать новую версию, сохранить новый manifest и описать отличие. Проверка exact-pixel потребует отдельно фиксированных шрифтов и renderer.
