# Синтетическое семейство DOCX для грамматики выделений 037

Корпус полностью создан для ArticleFlow: три похожих эталона по 44 абзаца,
два контрольных документа с новым содержанием и их испорченные входы. Здесь нет
текста или изображений реальной статьи. PNG-схема нарисована генератором.
Эталонные документы используют одни ресурсы Word и одинаковую секцию, чтобы
проверять извлечение правил, а не отказ из-за разных таблиц стилей.

`ground-truth.json` заранее задаёт иерархию: document defaults → роль абзаца →
смысловая роль фрагмента → класс символов. `manifest.json` перечисляет
эталоны, SHA-256, роли абзацев и точные диапазоны смысловых фрагментов.
Например, одно и то же слово в определении выделено, а в обычном тексте нет.
Латинский символ внутри обычного абзаца меняет цвет и шрифт без изменения
bold/italic; поэтому исходные `semantic_spans` объединяют его с соседним
текстом. Границу должен объяснять смысловой диапазон, а не исходный шрифт.
В каждом основном абзаце есть немаркированное тире U+2014 с отдельным цветом:
для него правило зависит от роли абзаца и класса символа, а не от явной inline
аннотации. Таким образом отдельно проверяются оба источника границ.

`heldout-input-i2.docx` получен стандартной нейтрализацией: геометрия и шрифты
испорчены, смысловые bold/italic сохранены. В `heldout-input-i1.docx` также
произвольно изменены bold/italic и границы runs; этот опыт требует предсказать
смысловые диапазоны из содержания. Оба должны привести к
`heldout-target.docx`; текст, OMML-формула и рисунок во всех трёх совпадают.
Содержимое held-out не входит в три обучающих эталона.

`heldout-hard-target.docx` — второй контроль из того же семейства с новым
текстом, четырьмя разделами вместо трёх, неодинаковым числом абзацев в
разделах (5/9/6/11) и двумя рисунками вместо одного. Всего 56 абзацев и 5
страниц вместо 44 абзацев и 4 страниц в первом контроле. Схема оформления,
ресурсы Word и свойства секции те же. `heldout-hard-input-i1.docx` сохраняет
текст, формулу и рисунки, но меняет границы runs, шрифты, размеры, цвета и
bold/italic. Содержательные абзацы второго контроля не совпадают дословно с
обучающими документами или первым контролем; служебное слово «Аннотация» общее
для всего семейства. Его номера, число повторений и
положение дополнительного рисунка не используются как признаки при обучении.

`negative-ambiguous.docx` — отдельный отрицательный контроль, его нельзя
включать в обучающую тройку. Два одинаковых по тексту и структурному контексту
абзаца имеют разные точные свойства текста. Для них нет безопасного правила
выбора по доступным признакам: ожидается конфликт и `needs_review`.

Воспроизведение в новой пустой папке:

```bash
PYTHONPATH=src python scripts/build_span_grammar037.py --output /tmp/span-grammar-v037
PYTHONPATH=src python -m unittest tests.test_span_grammar037 -v
```

Контрольный offline-прогон с **oracle-ролями абзацев и oracle-inline-метками из
манифеста**, без вызовов LLM: обучение по трём эталонам дало 0 конфликтов и
43 правила выделений. Для обоих новых входов I2 и I1 компиляция дала 0
неразрешённых диапазонов; содержание и точные свойства DOCX совпали с
`heldout-target.docx`, а LibreOffice показал 4/4 идентичных страницы при
144 DPI и нулевом допуске. Отрицательный контроль дал 4 конфликта знаков,
состояние `ambiguous` и отказ `SPAN_GRAMMAR_AMBIGUOUS`. Эти цифры проверяет
`tests/test_span_grammar037.py`; без установленного LibreOffice тест
пропускает только пиксельную часть.

На втором, структурно отличающемся контроле тот же oracle-fit по трём
эталонам дал 0 конфликтов и 43 правила; применение к I1 дало 0
неразрешённых диапазонов. Содержание и точные свойства DOCX совпали с
`heldout-hard-target.docx`, а LibreOffice показал 5/5 идентичных страниц.
Это также **oracle-прогон**: истинные роли абзацев и смысловые диапазоны взяты
из манифеста, поэтому результат измеряет переносимость грамматики и сборщика,
но не точность их предсказания LLM.

Это контролируемая синтетика. Успех на ней не доказывает качество для
произвольных научных статей или точность LLM при назначении ролей и диапазонов.
Пиксельная проверка зависит от версии рендерера и установленных шрифтов;
свойства DOCX проверяются отдельно.
