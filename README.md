# ArticleFlow

ArticleFlow — проект приложения для автоматического оформления научных статей в DOCX по шаблону, извлечённому из другой статьи DOCX. Цель — сократить ручную работу редактора и сохранить научное содержание.

**Состояние:** исследовательский прототип 0.4, 15 октября 2026 года. Каталог вариантов оформления и сборщик восстановили предоставленный образец точно: 10/10 новых сборок, 12 страниц, ноль отличающихся пикселей в закреплённой среде LibreOffice. Это контроль с правильным планом из исходника, без вызовов модели. [Отчёт 0.4](docs/research/renderer-004.md) и [предыдущие результаты LLM](docs/research/pilot-001.md) учитываются отдельно. Готового веб-приложения и обработки сотен статей пока нет.

В новых сериях используются только модели с подтверждённым выпуском после 30 июня 2026 года. Основная — GPT-6.1 Sol, выпущенная 29 сентября; [источники, registry и бюджет](docs/research/model-selection.md). Старые измерения GPT-4.1 остаются историческими и не участвуют в выборе актуальной модели.

Рабочий цикл: DOCX-образец → сильная модель/исследователь → проверенный TemplatePackage → пакет новых статей → малая модель → DocumentPlan → программная сборка DOCX → проверка → ZIP и отчёт. Подготовка шаблона и массовое применение имеют отдельные бюджеты и режимы вызовов.

API-ключи, реальные рукописи, извлечённые шаблоны конкретной статьи и ответы моделей не хранятся в Git. Публичны код, синтетические тесты и числовые результаты.

```bash
python -m pip install -e '.[dev]'
articleflow --help
python -m unittest discover -s tests -v
behave docs/product/scenarios/research-pilot.feature
```

Для PDF нужен `soffice` и зафиксированные шрифты. `extract-catalogue` и `render-catalogue` работают без API; порядок запуска — в [контракте 0.4](docs/tech/catalogue-renderer.md). Для платной серии нужны приватный DOCX, подготовленные исследователем annotations/definitions и `OPENROUTER_API_KEY`; обычные тесты API не вызывают. Runner 0.3 пока не выбирает варианты каталога 0.4: этот контракт предстоит измерить отдельно.
