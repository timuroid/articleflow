# ArticleFlow

ArticleFlow — проект приложения для автоматического оформления научных статей в DOCX по шаблону, извлечённому из другой статьи DOCX. Цель — сократить ручную работу редактора и сохранить научное содержание.

Git-происхождение: клон [timuroid/articleflow](https://github.com/timuroid/articleflow), ветка восстановления `codex/web017-recovery` основана на публичном `main` `cd8e890`.

**Состояние:** восстановлен рабочий Web 019: оформление по эталонам, ограниченный LLM-планировщик, ручная проверка, заполнение пропусков, версии и пакетный ZIP. Это новая реализация по сохранившейся истории, не найденный старый архив. CLI 0.7 сохранён.

**Рукопись и перенос 020:** [содержательная статья](docs/research/manuscript-reconstructed.md), [её исходный замысел](docs/research/manuscript-020-brief.md) и [новые прогоны](docs/research/evaluation-020.md). Новая авторская статья: 69/69 ролей/контекстов, 10 страниц; исправлены найденные дефекты оформления. Авторы и независимый benchmark ещё нужны.

**Проверка 019:** [серия 019](docs/research/evaluation-019.md) — разметка 152/152, точное оформление 6/6 development-пар, сохранность 7/7; настоящий эталон 12/12 страниц. Проверены Sol → шаблон → Luna и Qwen; ошибки прежних попыток учтены. Независимые реальные статьи и весь целевой продукт ещё не проверены. [Технический контракт](docs/tech/recovery-019.md).

**Статус развёртывания:** см. [STATUS.md](STATUS.md). Публичный `main` на `cd8e890` содержит CLI 0.7 без Web 017. Новый локальный код описан в [техническом срезе](docs/tech/web-017-local.md) и [структурной сборке](docs/tech/structure-017-local.md); прежний релиз описан отдельно в [карте утраты](docs/tech/web-017-recovery.md).

Отдельная [карта серий 010–016](docs/research/session-010-016-recovery.md) фиксирует сохранившиеся сведения и перечень недостающих первичных файлов. Она не подменяет публикацию кода, DOCX-корпуса и таблиц эксперимента.

После замены облачной среды точные файлы прежнего корпуса и научной рукописи не обнаружены; пользовательский эталон DOCX позднее найден в локальном архиве и сверен по SHA-256, его байты остаются вне Git. Для продолжения работы добавлены генератор и manifest **нового**, полностью синтетического [DOCX-корпуса из 19 файлов](datasets/synthetic-v1/map.md); сами файлы создаются локально. Сохранены [инвентаризация пропавшего](datasets/recovery-inventory.json), [заново составленный научный черновик](docs/research/manuscript-reconstructed.md) и [правила долговременного сохранения](docs/tech/data-preservation.md). Эти материалы не выдаются за восстановленные оригиналы.

[Серия 0.7](docs/research/source-aware-007.md): GPT-6.1 Sol и GPT-6 Luna дали по **10/10 полных совпадений** на предоставленном образце, включая все пиксели. Это I3 с доступным исходным оформлением; исходный gate восстановления очищенного текста не пройден, независимые реальные статьи не проверены.

Дополнительно проверена Qwen3.8-27B, выпущенная 14 августа 2026: [medium](docs/research/qwen-008.md) — **6/10** (три обрезания и один HTTP 429); [без reasoning](docs/research/qwen-009.md) — **9/10** (один HTTP 429). Все девять полученных документов второй серии совпали полностью, но строгий результат всей серии — 9/10. Медиана ответа без reasoning 94.79 с; Luna остаётся дешевле и быстрее среди проверенных I3-конфигураций. На обе серии Qwen подтверждено $0.271958960; накопленные подтверждённые расходы $3.059363045, дополнительно сохраняется резерв $0.07327168 для двух HTTP-ошибок без usage. Общий лимит $5 соблюдён вместе с резервом.

В новых сериях используются только модели с подтверждённым выпуском после 30 июня 2026 года. Основная — GPT-6.1 Sol, выпущенная 29 сентября; [источники, registry и бюджет](docs/research/model-selection.md). Старые измерения GPT-4.1 остаются историческими и не участвуют в выборе актуальной модели.

Рабочий цикл: DOCX-образец → сильная модель/исследователь → проверенный TemplatePackage → пакет новых статей → малая модель → DocumentPlan → программная сборка DOCX → проверка → ZIP и отчёт. Подготовка шаблона и массовое применение имеют отдельные бюджеты и режимы вызовов.

API-ключи, реальные рукописи, извлечённые шаблоны конкретной статьи и ответы моделей не хранятся в **публичном** Git. Для них требуется отдельная закрытая резервная копия; подтверждённые копии и хеши перечислены в STATUS и наблюдении развёртывания. Публичны код, синтетические тесты и числовые результаты.

```bash
python -m pip install -e '.[dev]'
articleflow --help
python -m unittest discover -s tests -v
behave docs/product/scenarios/research-pilot.feature
python scripts/build_synthetic_corpus.py  # создаёт 19 синтетических DOCX локально
python scripts/build_synthetic_corpus.py --verify
```

Для запуска восстановленного локального Web 017: `python -m pip install -e '.[web,dev]'`, затем `ARTICLEFLOW_DATA_DIR=/закрытый/каталог uvicorn articleflow.web017:create_app --factory --host 127.0.0.1 --port 8769`. Публичный сервер ставится по [инструкции для Caddy](docs/tech/deployment-caddy-017.md); без обратного прокси и авторизации этот запуск использовать только на loopback.

Для PDF нужен `soffice` и зафиксированные шрифты. `extract-catalogue` и `render-catalogue` работают без API; порядок запуска — в [контракте 0.4](docs/tech/catalogue-renderer.md). Для платной серии нужны приватный DOCX, подготовленные исследователем annotations/definitions и `OPENROUTER_API_KEY`; обычные тесты API не вызывают. `catalogue-trials` измеряет новый выбор вариантов; runner `trials` сохраняет исторический контракт 0.3.
