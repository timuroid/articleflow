# ArticleFlow

ArticleFlow — проект приложения для автоматического оформления научных статей в DOCX по шаблону, извлечённому из другой статьи DOCX. Цель — сократить ручную работу редактора и сохранить научное содержание.

**Состояние:** исследовательский прототип 0.7, 15 октября 2026 года. В отдельном режиме I3 модель назначает роли, а compiler применяет шаблон к исходному DOCX, сохраняя допустимые исходные свойства. Готового веб-приложения и обработки сотен статей пока нет.

**Статус развёртывания на 17 октября 2026 года:** в публичной ветке `main` по-прежнему только CLI 0.7. Исходники Web 017, подготовленные в прежней локальной среде, не были отправлены в GitHub и сейчас требуют восстановления из приватного релиза. [Что было сделано и каких файлов нет](docs/tech/web-017-recovery.md) · [инструкция по развёртыванию после получения релиза](docs/tech/deployment.md) · [дополнительные продуктовые требования](docs/product/structure-017.md) · [исторический журнал исследования](docs/research/session-017-recovery.md). Клонирование этой ветки и установка `pyproject.toml` не запустят веб-интерфейс.

Отдельная [карта серий 010–016](docs/research/session-010-016-recovery.md) фиксирует сохранившиеся сведения и перечень недостающих первичных файлов. Она не подменяет публикацию кода, DOCX-корпуса и таблиц эксперимента.

После замены облачной среды точные файлы прежнего корпуса, пользовательского DOCX и научной рукописи не обнаружены. Для продолжения работы добавлены генератор и manifest **нового**, полностью синтетического [DOCX-корпуса из 19 файлов](datasets/synthetic-v1/map.md); сами файлы создаются локально. Сохранены [инвентаризация пропавшего](datasets/recovery-inventory.json), [заново составленный научный черновик](docs/research/manuscript-reconstructed.md) и [правила долговременного сохранения](docs/tech/data-preservation.md). Эти материалы не выдаются за восстановленные оригиналы.

[Серия 0.7](docs/research/source-aware-007.md): GPT-6.1 Sol и GPT-6 Luna дали по **10/10 полных совпадений** на предоставленном образце, включая все пиксели. Это I3 с доступным исходным оформлением; исходный gate восстановления очищенного текста не пройден, независимые реальные статьи не проверены.

Дополнительно проверена Qwen3.8-27B, выпущенная 14 августа 2026: [medium](docs/research/qwen-008.md) — **6/10** (три обрезания и один HTTP 429); [без reasoning](docs/research/qwen-009.md) — **9/10** (один HTTP 429). Все девять полученных документов второй серии совпали полностью, но строгий результат всей серии — 9/10. Медиана ответа без reasoning 94.79 с; Luna остаётся дешевле и быстрее среди проверенных I3-конфигураций. На обе серии Qwen подтверждено $0.271958960; накопленные подтверждённые расходы $3.059363045, дополнительно сохраняется резерв $0.07327168 для двух HTTP-ошибок без usage. Общий лимит $5 соблюдён вместе с резервом.

В новых сериях используются только модели с подтверждённым выпуском после 30 июня 2026 года. Основная — GPT-6.1 Sol, выпущенная 29 сентября; [источники, registry и бюджет](docs/research/model-selection.md). Старые измерения GPT-4.1 остаются историческими и не участвуют в выборе актуальной модели.

Рабочий цикл: DOCX-образец → сильная модель/исследователь → проверенный TemplatePackage → пакет новых статей → малая модель → DocumentPlan → программная сборка DOCX → проверка → ZIP и отчёт. Подготовка шаблона и массовое применение имеют отдельные бюджеты и режимы вызовов.

API-ключи, реальные рукописи, извлечённые шаблоны конкретной статьи и ответы моделей не хранятся в **публичном** Git. Для них требуется отдельная закрытая резервная копия; сейчас её наличие не подтверждено. Публичны код, синтетические тесты и числовые результаты.

```bash
python -m pip install -e '.[dev]'
articleflow --help
python -m unittest discover -s tests -v
behave docs/product/scenarios/research-pilot.feature
python scripts/build_synthetic_corpus.py  # создаёт 19 синтетических DOCX локально
python scripts/build_synthetic_corpus.py --verify
```

Для PDF нужен `soffice` и зафиксированные шрифты. `extract-catalogue` и `render-catalogue` работают без API; порядок запуска — в [контракте 0.4](docs/tech/catalogue-renderer.md). Для платной серии нужны приватный DOCX, подготовленные исследователем annotations/definitions и `OPENROUTER_API_KEY`; обычные тесты API не вызывают. `catalogue-trials` измеряет новый выбор вариантов; runner `trials` сохраняет исторический контракт 0.3.
