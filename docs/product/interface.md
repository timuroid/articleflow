# Интерфейс приложения

## Принципы

Интерфейс ведёт редактора от образца к повторно используемому шаблону и готовой статье. Основные действия доступны без знания OOXML, названий моделей и устройства очереди. Технические идентификаторы доступны в деталях ошибки для поддержки. Структурный просмотр в браузере помогает проверить роли и текст, но не обещает точное отображение страниц Word.

Основная платформа MVP — настольный браузер; минимальная рабочая ширина 1024 px, на меньшей ширине панели становятся последовательными. Все основные операции доступны с клавиатуры; статус передаётся текстом и значком, а не только цветом. Диалоги управляют фокусом, сообщения об изменении этапа объявляются через aria-live. Большие документы используют виртуализацию списка с сохранением перехода к выбранному блоку.

## Навигация и маршруты

| Маршрут | Экран | Основное действие |
| --- | --- | --- |
| `/templates` | Список шаблонов | Создать шаблон |
| `/templates/new` | Загрузка образца | Проанализировать образец |
| `/templates/:id/versions/:versionId` | Правила и вопросы шаблона | Утвердить версию / создать новую |
| `/articles/new` | Загрузка статьи и выбор шаблона | Начать оформление |
| `/jobs` | История обработок | Открыть запуск |
| `/jobs/:id` | Этапы, вопросы, результат | Ответить / скачать / повторить |
| `/batches/new` | Множественная загрузка и параметры пакета | Загрузить файлы и начать обработку |
| `/batches/:id` | Очередь статей, частичные результаты и экспорты | Скачать ZIP / повторить ошибки |
| `/settings` | Пространство и настройки | Настроить обработку и хранение |

Заголовок приложения показывает текущее рабочее пространство. Навигация состоит из «Статьи», «Шаблоны», «Настройки». Доступные действия рассчитывает сервер; скрытие кнопки не заменяет проверку полномочий.

## 1. Пустое состояние и список шаблонов

При отсутствии шаблонов: «Загрузите оформленную статью DOCX. Мы извлечём из неё правила для следующих статей». Кнопка «Создать шаблон». Нет заранее придуманного универсального научного шаблона.

Карточка шаблона содержит название, последнюю утверждённую версию, наличие черновика, автора изменения и дату. Поиск по названию, фильтр по статусу. В статье всегда выбирается конкретная версия; изменение последней версии не меняет уже созданные задания. Архивный шаблон доступен в истории, но не предлагается для новых запусков.

## 2. Создание шаблона

Поля: название (1–120 символов), необязательное описание, DOCX-образец. Drag-and-drop дублируется обычным выбором файла. До отправки отображаются имя и размер. Проверка расширения в браузере предварительная; ошибки серверной проверки отображаются у файла.

Перед LLM-анализом показано, какие данные передаются выбранному провайдеру: фрагменты текста и признаки оформления, цель передачи и ссылка на политику пространства. Отдельное действие «Разрешить анализ текста» фиксирует разрешение на эту версию исходника и конфигурацию провайдера. Ключ API в форме отсутствует. При отказе доступны локальный разбор и его ограничения, но LLM-анализ не начинается; полноценный ручной редактор шаблона без LLM не является обещанием MVP.

После загрузки — этапы «Проверяем файл», «Извлекаем оформление», «Определяем структуру», «Готовим правила». Не показывать фиктивные проценты. При сетевом разрыве интерфейс восстанавливает состояние по job ID.

## 3. Редактор правил шаблона

Три зоны: список ролей и вопросов слева, структурный образец в центре, параметры выбранной роли справа. В узком окне зоны переключаются вкладками. Отображаются название роли, количество наблюдений и примеры с переходом к исходному блоку.

Группы правил:

- Страница: размер, ориентация, поля, колонки, параметры раздела.
- Абзацы: шрифт и кегль по умолчанию, выравнивание, интервалы, отступы, запрет висячих строк, связь со следующим абзацем.
- Роли: название, авторы, организации, аннотация, ключевые слова, заголовки уровней, основной текст, подписи, библиография.
- Объекты: правила подписи, ширины таблиц и встроенных изображений в пределах поддерживаемого профиля.
- Структура: обязательность ролей, допустимая повторяемость, порядок. По умолчанию порядок статьи сохраняется.

У параметра есть значение, единица, происхождение («Из образца», «Задано вручную», «Предположение») и состояние подтверждения. Пример неопределённости: «Найдено два варианта основного текста: 12 pt и 14 pt. Выберите правило». Числовая оценка модели не называется вероятностью правильности.

Наблюдение и правило различаются: для неизвестной подписи рисунка показывается «В образце не найдено», а не случайное значение. Пользователь может задать правило вручную, пометить роль необязательной или оставить неподдерживаемой с объяснением последствий.

Кнопки: «Сохранить черновик», «Проверить правила», «Утвердить версию». Утверждение заблокировано при обязательных вопросах или противоречивых параметрах. В подтверждении показаны имя, номер версии, остаточные ограничения и сводка изменений. После утверждения редактирование создаёт новый черновик. При конфликте двух редакторов экран предлагает обновить данные и сопоставить изменения; чужие правки не затираются.

## 4. Загрузка статьи

Пользователь выбирает файл, шаблон и его утверждённую версию. Перед стартом видит краткую сводку: имя статьи, версия шаблона, лимит размера и установленный предел расходов. Если оценка расходов недоступна, интерфейс не придумывает сумму. При отсутствии разрешения внешней обработки показывается тот же явный шаг согласия, что для образца.

Для одиночного документа «Проверить и оформить» создаёт один запуск. Пакет создаётся отдельным действием, описанным ниже. Повторное нажатие не создаёт дубликатов. Для отслеживаемых изменений: «Примите или отклоните исправления в Word и загрузите файл повторно». Оригинал не меняется.

## 5. Выполнение и вопросы

Экран запуска содержит имя статьи, неизменяемую версию шаблона, этап, время начала, последние события и кнопку отмены для нетерминальных состояний. Состояния API сопоставляются с понятными подписями:

| Статус | Подпись | Действие |
| --- | --- | --- |
| `queued` | В очереди | Отменить |
| `running` | Обработка: текущий этап | Отменить |
| `needs_review` | Нужна ваша проверка | Ответить на вопросы |
| `cancel_requested` | Отменяем обработку | Ожидать завершения отмены |
| `cancelled` | Обработка отменена | Создать новый запуск |
| `completed` | Проверки пройдены | Скачать DOCX и отчёт |
| `completed_with_warnings` | Готово с замечаниями | Просмотреть замечания, скачать |
| `failed` | Не удалось подготовить результат | Открыть причину, повторить при допустимости |

Вопрос показывает фрагмент статьи, найденную роль, альтернативы и причину остановки. Варианты: выбрать роль, подтвердить допустимый порядок, исправить правило в новой версии шаблона, отказаться от запуска. Исходный текст внутри этого интерфейса не редактируется. «Пропустить все проверки» отсутствует. Ответы относятся к review revision; устаревшая форма не применяется к новому состоянию.

Примеры: «Этот абзац — заголовок раздела или основной текст?», «Шаблон требует аннотацию, но мы её не нашли». Для отсутствующей аннотации возможны новая статья с аннотацией, новый шаблон без обязательного требования либо отмена; кнопки «Придумать аннотацию» нет.

## 6. Результат

Верхняя панель показывает итог проверки, число блокирующих ошибок (в доступном результате всегда 0), предупреждений и непроверенных правил. Действия: «Скачать DOCX», «Скачать отчёт», «Открыть исходник», «Создать повторный запуск». Имя файла безопасное, например `article-formatted-v1.docx`.

Вкладки: «Обзор», «Изменения оформления», «Проверка содержания», «Замечания». Для изменения показываются источник, роль и значения до/после, например «Основной текст: интервал после 8 pt → 0 pt». Не показывать всю рукопись как текстовый diff, если поменялись только свойства оформления.

Структурный preview помечен «Структура документа. Разбивку на страницы проверьте в Word». Если позже появится серверный PDF-preview, он будет подписан названием движка и версией. Потеря объекта, текста или связи блокирует итоговый DOCX; пользователь видит отчёт и исходник, а не потенциально испорченный файл.

## 7. История, повтор и удаление

История показывает имя, шаблон и версию, статус, дату, владельца и срок хранения. Повтор использует тот же исходник и зафиксированную версию; новая версия выбирается явно и создаёт новый запуск. Новый запуск получает отдельную запись, стоимость и ссылки на предыдущий.

Удаление файла подтверждается списком последствий: исходник, извлечённый текст, артефакты, связанные активные задания. После подтверждения скачивание блокируется сразу; фактическое удаление асинхронно. Для утверждённого шаблона сначала предлагается архивирование. Изменение retention не обещает удалить данные у внешнего провайдера, если его договор этого не позволяет.

## 8. Ошибки и доступность

Ошибки должны содержать причину и следующий шаг. Примеры: «Файл больше 25 MiB», «Формат DOCM не поддерживается», «Модель временно недоступна; повторите позже», «Проверка обнаружила изменение текста: результат не выдан». К сообщению добавляется request ID без ключей и текста рукописи.

При потере соединения показывается «Связь прервана, обработка может продолжаться», а не «Ошибка обработки». При истёкшей сессии после входа пользователь возвращается к тому же запуску. Ошибка чужого job ID не раскрывает название чужой статьи.

## 9. Правила внутри абзаца и объектов

В редакторе TemplatePackage добавляются вкладки «Выделения в тексте», «Подписи и рисунки», «Служебные надписи». Редактор задаёт семантическое условие («определяемый термин»), стиль (жирный/курсив), поведение при неоднозначности и синтетический пример. Конкретный выделенный фрагмент образца показывается как evidence, а не глобальная позиция для всех статей. UI визуально отделяет «сохранить авторское выделение» от «определить новое по правилу».

Правило подписи показывает тип объекта, связь с изображением, расположение, исходный номер, label и научный текст. Настройки размера имеют единицы и preserve aspect ratio. Для literals доступны allowlist и защита от двойного префикса. После изменения всегда создаётся новая версия.

## 10. Пакет статей и архив

Пользователь выбирает множество DOCX, одну версию шаблона и режим «Один проход» либо явно доступный «С исправлениями». По умолчанию исследуемый путь — один проход; продукт не обещает, что любая статья поместится или пройдёт его. В интерфейсе не требуется знать model ID, но режим, ограничения и предел расходов видны.

Список файлов показывает имя, размер, upload progress и причину отказа по каждому элементу. Предлагаемые ограничения — до 300 файлов/2 GiB, сервер публикует фактические лимиты. После подтверждения состава и обработки текста создаётся sealed batch. Невалидные файлы можно оставить как явные ошибки; готовые начинают обработку. Кнопка «Начать» идемпотентна.

Экран batch показывает счётчики «В очереди / Обрабатывается / Готово / Нужна проверка / Ошибка», текущий файл и бюджет. Статьи идут по очереди; review одной не удерживает очередь. Готовый DOCX скачивается сразу. При потере связи состояние восстанавливается с сервера, файлы не загружаются заново без необходимости.

«Скачать готовые ZIP» создаёт export snapshot: сообщение «Готово 182 из 200; 12 с ошибками, 6 ожидают проверки». Manifest включает все 200 элементов, архив только прошедшие проверки DOCX. Нельзя назвать такой архив полным успехом. Позднее можно создать новый архив; предыдущий не меняется. Отмена оставляет уже готовые результаты. Повтор ошибок создаёт новую run generation и не переобрабатывает успешные без явного действия.

## 11. Исследовательский отчёт

В первой итерации это артефакты исследования, отдельный сложный web-dashboard не требуется. Отчёт содержит method/input protocol/template/model/render versions, 10 строк испытаний, exact pixel status, content integrity, фактическое число вызовов, время и расходы. Reconstruction и transfer показаны отдельно. «10/10 на образце» не подписывается «100% точность на любых статьях».

## Реализованный срез 019

В однопользовательском интерфейсе доступны отдельное согласие на модельный анализ эталонов/статей, выбор обязательных сведений, варианты оформления с источниками, заполнение пропусков и повторная сборка без LLM. Последние 50 пакетов доступны после обновления страницы. Состояния ожидания/ошибки видны; кнопки блокируются на время операции. Версии и исходники сохраняются. [Контракт и ограничения](../tech/recovery-019.md).

## Веб-срез 022: цикл извлечения и PDF

Загрузка эталона автоматически запускает фоновую проверку. В карточке шаблона
показываются этап, число проверенных страниц, итог и ограничение переноса.
Доступны повторный запуск «Проверить и доработать шаблон», PDF восстановленного
образца и приватный ZIP полного каталога. Вариант с единственным лидером по
наблюдениям предлагается автоматически. При ничьей поле остаётся пустым.

В карточке статьи доступны PDF текущей ревизии, результат контроля всех
страниц и номера страниц с замечаниями. Непроверенный результат остаётся
черновиком. Восстановление образца и перенос на новый текст обозначаются
отдельно; старые версии не получают новую проверку задним числом.

Для 022-v1 карточка различает контроль каталога и рабочего сборщика. Результат
каждой повторной сборки показывает число точных страниц, а при провале
сохраняются ссылки на исходный PDF и оба результата рабочего сборщика.
Старая проверка без этого контракта помечается неподтверждённой; повторный
запуск заново извлекает свойства в новой неутверждённой версии, сохраняя
смысловые назначения. Старые версии/результаты не удаляются.

## Срез 023: обучение с малой моделью

На карточке шаблона доступно поле дополнительных требований и действие
«Обучить шаблон и проверить с Qwen». Перед отправкой текста требуется согласие.
Показываются итерации, покрытие ролей, точные страницы и причины остановки.
После совпадения пользователь отвечает только на возникшие вопросы и
сохраняет версию. Обязательность блоков можно уточнить отдельно; каждый ответ
создаёт новую версию. Если отсутствует наблюдавшийся блок без решения о его
необязательности, новая статья остаётся draft с явным вопросом.

## Режимы 024

При запуске обучения пользователь выбирает «Автоматический» (по умолчанию)
или «С уточнениями». Автоматический режим сохраняет версию только после всех
контрольных проверок. Экран показывает последовательность стадий, итерации,
конфликты и совпадение страниц. Блок «Уточнить требования во время работы»
сохраняет текст, не сбрасывая ввод при обновлении статуса. Показываются номера
принятого и применённого уточнения. Если цикл уже завершён, объясняется необходимость
нового запуска. Неприменённое уточнение блокирует автоматическое сохранение.
В результате обработки статьи показаны роль и прежняя/новая позиция перемещённых
блоков. Обязательность ненаблюдавшихся/неподтверждённых требований не выдумывается.
