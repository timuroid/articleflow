# Допущения и вопросы

Это реестр решений версии 0.1. Ниже перечислены рабочие предположения, а не ответы, полученные от заказчика. Они позволяют начать проектирование; вопросы уточняются до соответствующего этапа реализации.

| ID | Вопрос | Рабочее предположение | Когда решить / кто |
| --- | --- | --- | --- |
| OQ-01 | Какие образцы и статьи реально обрабатываются? | Нужны 3 образца и минимум 20 разрешённых статей; сейчас не предоставлены | До проверки DOCX-конвейера / владелец продукта |
| OQ-02 | Какие правила нельзя вывести из образца? | Редактор подтверждает обязательность и порядок вручную | До утверждения первого шаблона / редактор |
| OQ-03 | Тип размещения и пользователи? | Веб-приложение, рабочие пространства, сначала небольшая редакция | До инфраструктуры / владелец продукта |
| OQ-04 | Допустима ли отправка рукописей внешней модели? | Только по явному разрешению; провайдер, регион и retention требуют согласования | До внешней обработки / владелец данных |
| OQ-05 | Провайдер и модель? | Адаптер OpenAI-compatible API; OpenRouter — возможный первый провайдер, не подтверждённая интеграция | До LLM-spike / разработчик и владелец |
| OQ-06 | Какие Word, ОС и шрифты являются эталоном? | Word для проверки результата; LibreOffice только вспомогательно | До визуальной приёмки / редактор |
| OQ-07 | Нужны ли сложные объекты, две колонки и колонтитулы? | Поддержка ограничена матрицей; корпус определит следующие расширения | До фиксации MVP / редактор |
| OQ-08 | Можно ли менять порядок разделов? | По умолчанию нельзя; только явное правило, решение и проверяемые ссылки | До структурных преобразований / редактор |
| OQ-09 | Срок хранения? | Рабочее предложение: 30 дней для статей и результатов, версии шаблонов до архивации/удаления | До пилота / владелец данных |
| OQ-10 | Нагрузка, бюджет и время? | Один документ на запуск, 25 MiB, до 120 s целевого p95 для эталонного класса | После измерений / команда |
| OQ-11 | Нужны пакетная обработка и биллинг? | После MVP | После пилота / владелец продукта |
| OQ-12 | Какой юридический статус и лицензия кода? | Лицензия пока не выбрана; права на образцы подтверждаются отдельно | До публичного распространения / владелец |

## Предложенные решения

Python/FastAPI, React/TypeScript, PostgreSQL, Redis и S3-совместимое хранилище — исходная архитектурная гипотеза. Нельзя считать выбор зависимостей доказательством поддержки всех DOCX. Первый технический этап — исследовательский прототип сохранения OOXML на корпусе, затем уточнение поддержки и стоимости.

При закрытии вопроса добавить дату, основание и ссылку на ADR или изменённое требование. При изменении предположения обновить связанные сценарии и контракты одним изменением.
