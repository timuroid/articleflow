# Управляемое исправление сборщика внутренним агентом — 034

Дата: 18 октября 2026. Реализация: commit `4dbd4df`. Рабочая ветка
`codex/web017-recovery`; сервер в этой серии не обновлялся.

## Вопрос и результат

Может ли внутренний агент исправлять код исполнения, если изменение инструкции
учителя больше не улучшает результат? Да, для проверенной ошибки порядка это
получилось в полном автоматическом цикле. Универсальная готовность не достигнута:
на длинном документе осталось 30 конфликтов, а отдельный опыт с inline-правилами
не прошёл независимую проверку.

Ранее агент менял семантические инструкции, но не реализацию сборки. Повторение
такого шага не исправляет ошибку алгоритма. В034 добавлена ограниченная ветка
изменения исходников. Это инженерный эксперимент с внутренним code-agent;
исследователь улучшал диагностику и протокол между сериями, но не редактировал
кандидатные патчи внутри опубликованных прогонов.

## Метод

1. Обычный агент извлекает шаблон и проверяет воспроизведение эталона и независимо
   испорченных входов. Ошибки транспорта и исчерпание бюджета не запускают ремонт.
2. При отказе система сохраняет ответы моделей и собирает воспроизводимые случаи.
   Для ошибки до семантического этапа поддержан отдельный instance replay.
3. Большая модель получает доступный код и структурную диагностику development
   случаев. Она возвращает точные замены разрешённых фрагментов исходников.
4. Кандидат работает в Docker без сети, секретов и доступа к эталонным выходам.
   Проверяющий код остаётся вне контейнера и не подлежит изменению агентом.
5. Проверяются содержание, порядок, свойства OOXML, все растровые страницы и
   отдельные регрессии. Частичное улучшение сохраняется только для продолжения
   поиска. Сертификация требует прохождения всех проверок.
6. После принятия кода автоматически запускается новый полный цикл с новыми
   вызовами teacher/student. При его отказе готовность шаблона не объявляется.

Подробная схема, границы изоляции и интерфейс: [технический контракт](../tech/managed-repair-034.md).
Модели: `openai/gpt-6.1-sol` для code-agent/teacher, `qwen/qwen3.8-27b` для student;
реестр происхождения моделей сохранён отдельно. В repair replay ответы student
заморожены, поэтому изменения результата связаны с исполнителем. В fresh/managed
опытах ответы получены заново через OpenRouter с единым журналом расходов.

Для контролируемого внесения дефекта использован исторический `order024.py` из031
и `rules023.py` из032. Это не новые неизвестные ошибки и не независимый test set.
Семь собственных синтетических регрессий создаёт отдельный генератор с seed34001;
текст применения отличается от текста обучения. В финальном managed опыте две
регрессии доступны диагностике, пять скрыты. К ним добавлены три случая текущего
эталона: обычный, с изменённым оформлением и с перестановками. Агент не выбирает
повреждения и не меняет правильные ответы. Узкий набор регрессий не доказывает
отсутствия ошибок на других документах.

Серии034 и034b не следует объединять в единую оценку точности: менялись доступная
диагностика и протокол. 034d не измеряет эффект исправления парсера корректно:
кэшированный каталог исключал его влияние. Предыдущие результаты сохранены, а
ошибка стенда исправлена повторным извлечением каждого эталона кандидатом.

## Подтверждённый сквозной результат

`managed034b-live`: агент сам обнаружил проблему порядка, изменил сборщик,
проверил 10 случаев, затем повторно создал и проверил шаблон. Свойства оформления,
содержание и все страницы эталона/применимых повреждений совпали. Всего9 реальных
API-вызовов, известная стоимость **0,078181015 USD**. Ремонт занял293,63с, первый
семантический цикл69,35с, повторный60,30с: сумма этих фаз423,28с, плюс накладные
расходы между ними. Поле `final_learning_seconds` в JSON относится только к
последнему семантическому циклу; это не время всей цепочки.

Отдельный fresh recheck принятого034b-order:4 вызова,53,52с,0,017558075 USD,
`reference_verified`. Он использует тот же development-эталон OSU и не является
независимым доказательством переноса.

Известная стоимость перечисленных034 опытов: **1,014838575 USD**; по сохранённым
meta этих опытов нет вызовов с неизвестной стоимостью. Это не остаток счёта и не
полные исторические расходы проекта. Времена получены на общей среде, часть
опытов пересекалась; оценок P50/P90 и оптимального лимита итераций нет.

## Что объясняет плато

Ошибка сборки не исправляется повторной семантической разметкой. Даже после
разрешения менять код результат зависит от наблюдаемой диагностики: один код
ошибки недостаточен для безопасной правки. Нулевое число unresolved недостаточно:
inline-патч устранил симптом, но был отвергнут по конечному результату.

Для длинного документа первое структурное исправление отделило привязки
нумерации от идентичности оформления. Оно уменьшило конфликты, но осталось30.
Это счётчик неоднозначностей, а не процент ошибочных абзацев. Две попытки не
устанавливают фундаментальный предел модели или оптимальный бюджет. Следующий
обоснованный шаг — диагностировать оставшиеся различия по структуре и контексту,
не сливать точные варианты отступов и не ослаблять gate совпадения.

## Проверки и границы

178 unittest,4 исполнимых BDD-сценария; синтаксис JavaScript проверен. Реальный
контейнерный probe: UID65534, чтение закрытого host-файла невозможно, запись в код
невозможна, сетевых маршрутов нет. Это проверка выбранного профиля изоляции,
не полный аудит безопасности многопользовательского сервиса.

Система не поддерживает любые OOXML, не доказала100% на независимом корпусе,
не сравнивала размеры моделей и локальные квантизации в этой серии. Backend034
требует настроенного Docker image. Отказ на длинном документе остаётся открытым.

## Сохранение и воспроизводимость

- [Агрегаты](engine-repair-034.json): все успешные и неуспешные серии, расходы,
  проверки и частичные улучшения; без текстов документов и сырых ответов.
- [Архив собственных исходников](source-snapshots-034.json.gz):21 снимок базовых
  и кандидатных движков,74 уникальных файла с SHA-256. Это код, не корпус DOCX.
- `scripts/archive_sources034.py` пересобирает архив;
  `scripts/restore_sources034.py` проверяет hashes и восстанавливает выбранный
  снимок в новый каталог, ничего не исполняя.
- `scripts/experiment_repair034.py` запускает оплачиваемые контролируемые опыты;
  `scripts/check_worker034.py` проверяет изоляцию;
  `scripts/summarize_repair034.py` экспортирует только агрегаты.

Пример восстановления принятого автономного патча:

```sh
python scripts/restore_sources034.py \
  --bundle docs/research/source-snapshots-034.json.gz \
  --experiment managed034b-live/run/repair/attempt-1/engine \
  --output /tmp/engine034-restored
```

Реальные DOCX/PDF, частные ответы моделей и журналы API находятся **только локально**
в `artifacts/`. Независимое закрытое хранилище не настроено; восстановимость этих
байтов не обещается. Архив кода и агрегаты не заменяют исходные исследовательские
данные. Воспроизвести публичные синтетические guards можно из генератора;
воспроизведение конкретных реальных опытов требует соответствующих закрытых
входов и окружения шрифтов. Dockerfile сохраняет зависимости, profile — ID image;
сам образ в публичный registry этой серией не опубликован.
