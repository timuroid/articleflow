# Серия 018 — проверка восстановленного Web 017

Протокол зафиксирован до запуска 17 октября 2026 года. Проверяется код
`238a0c6191bae675efcfc9eb02174f81d63baf03`, без изменения алгоритма по результатам.
Это бесплатная оценка детерминированного приложения, не свежая серия LLM.

## Наборы и условия

- Синтетический `synthetic-v1`: 6 обучающих образцов (по два на профиль),
  6 пар source/reference, один документ с отсутствующими полями. Все 19 файлов
  проверяются по опубликованному manifest. Evaluation часть синтетическая,
  создана тем же генератором; это не независимый перенос на реальные статьи.
- Вариант оформления для каждой роли выбирается только по частоте наблюдений
  в двух train-образцах, при равенстве — по ключу. Выбор фиксируется до теста.
  Слияние конфликтов этим способом — экспериментальная конфигурация,
  не подтверждение редактором правильности всех стилей.
- Gold-роли задаются evaluator по структуре генератора. Два абзаца ключевых
  слов относятся к keywords, обе рабочие заметки — к editorial. Разметка
  не передаётся сборщику. Рабочий путь использует собственные suggest_roles.
- 24 перестановки четырёх явно подписанных частей аннотации проверяют
  инвариант порядка. Это 24 входа, а не повторные вызовы модели.
- Приватный пользовательский эталон с SHA-256 `2a299af6…` проверяется отдельно:
  целостность и диагностическое сравнение с самим образцом, без gold-ролей.
- HTTP-пакеты 1, 20 и 200 синтетических файлов в изолированном локальном
  хранилище; 201 файл должен быть отклонён. TestClient включает окончание
  фоновой задачи в wall time; цифра не является production throughput.

## Метрики и критерии

1. DOCX открывается ZIP/XML-парсером; все исходные блоки представлены ровно
   один раз в article + editorial, кроме отдельно учтённых заполнителей.
2. Независимый evaluator сравнивает мультимножества XML payload блоков после
   удаления только разрешённого форматирования; отдельно — точные таблицы,
   OMML, drawing, hyperlink и неизменность всех остальных частей DOCX.
   Содержимое, links и semantic spans не удаляются из сравнения.
3. Micro-F1/accuracy ролей по всем блокам, exact role sequence по документу,
   правильный порядок частей аннотации, отделение обеих editorial notes.
4. Неподтверждённые роли и отсутствующие поля должны сохранять draft;
   финальная выдача и results/ ZIP заблокированы. Такой отказ — корректная
   защита, но не готовая к публикации статья.
5. Для шести пар: равенство секции и styles.xml, exact pixels при 144 DPI,
   число/размер страниц и доля различных пикселей. Golden содержит иное
   оформление того же синтетического содержания; заметки в него не входят.
   Несовпадение не скрывается выравниванием, обрезкой или маской.
6. До визуального сравнения один golden рендерится 10 раз в чистых профилях.
   Exact результат действителен только при стабильных raster hashes.
   Renderer/version, font paths/hashes и фактическое имя гарнитуры сохраняются.
7. Время структурной сборки: 10 повторов каждого из семи входов, p50/p95;
   повторы не увеличивают число независимых документов.

Исторические сводки 001–009 читаются из CSV/JSON как ранее записанные
результаты. 010–017 без исходных таблиц остаются сообщениями прежнего диалога.
Новые платные запросы запрещены до восстановления накопленного ledger,
закрытого prompt и проверки текущего лимита: старые cap $5 и более поздний
cap $14.875251924 описывают разные этапы и не дают нового нулевого бюджета.
Внешних model calls, retries и расходов в этой серии: 0.

## Сохранение

В Git публикуются evaluator, протокол, все числовые attempts и сводка.
DOCX, PDF, PNG и приватные входы остаются в `artifacts/`; проверенная копия
с manifest сохраняется вне Work. Код и отчёт отправляются в разрешённую
ветку GitHub, SHA проверяется чтением удалённого ref.
