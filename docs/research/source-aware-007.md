# Source-aware 007: точная сборка с исходными свойствами DOCX

Дата: 15 октября 2026 года. Этот этап проверяет **отдельный профиль I3**: compiler получает оформление входного DOCX, модель назначает только смысловые роли. Точное совпадение здесь не означает восстановление удалённого оформления из чистого текста. Исходный golden и прежние неуспешные результаты I1/I2 не изменены.

## Что реализовано

1. [Source marks](../tech/semantic-marks.md): сохранение исходных bold/italic/super/subscript, включая пробелы и пунктуацию. Шрифты, интервалы и геометрия не входят в этот payload.
2. [Source-aware compiler](../tech/source-aware.md): применение однозначных контекстных правил, сохранение допустимых исходных вариантов, однозначное сопоставление отличающихся шрифтов/кегля/интервалов. Неоднозначность и несовместимость ресурсов дают review.
3. Отдельный runner свежих role-only запросов с замороженными prompt/schema/settings, общим ledger и одним POST на попытку. Неудача не заменяется repair.

Compiler читает свойства именно **обрабатываемой статьи**. Target oracle и golden используются только evaluator. Создаётся новый body и DOCX. Для уже оформленного образца сохранение допустимых source properties является основной причиной точного совпадения; модель не предсказывает эти свойства с нуля.

## Дополнительные выделения: offline replay

Повторно собраны все девять валидных планов 0.5 с прежними контекстными правилами и новым source marks payload. Содержимое и проверяемые bold/italic/vertical точны в 9/9. Exact pixels — 0/9; доля различий 6.1594–11.8739%. Старый десятый невалидный ответ не исправлялся и остаётся в журнале прежней серии. Новых API-вызовов для replay нет.

Это отдельный входной протокол. Успех сохранения авторских выделений не засчитывается как их правильное предсказание моделью.

## Свежие модельные серии I3

Модели выпущены после июня 2026 года; даты подтверждены в [registry](models.json). Модель видит определения 42 ролей, текст 178 блоков, наличие объектов и принадлежность таблице. Формат ответа — только `id/role`. Compiler получает source DOCX отдельно. Для обеих моделей фиксируются `reasoning=medium`, `max_tokens=8192`, одинаковые prompt/schema, TemplatePackage, RulePack и renderer.

## Проверка причины неоднозначности

В диагностической копии исходника поменяны местами параметры двух пустых абзацев. При одном и том же замороженном шаблоне нейтральное содержимое и вход прежнего planner совпадают, но два golden PDF отличаются на 2.0039% пикселей. Оба назначения входят в разрешённые варианты каталога. Исходные semantic marks тоже совпадают, кроме provenance hash файла.

Следовательно, наблюдаемый каталог и очищенный вход не задают единственный исходный visual output. Эта проверка не доказывает невозможность хорошо оформлять новые статьи по явным правилам; она показывает недостаточность текущего контракта для угадывания произвольных удалённых различий. Введение индивидуальных правил по тексту, block ID или порядковому номеру образца запрещено.

## Инженерные проверки

57 unittest и 14 Gherkin-сценариев. Проверяются hashes, coverage, конфликты spans, отсутствие target oracle на application path, сохранение flags после удаления source на этапе нейтральной сборки, новый синтетический текст, исправление неправильного шрифта/кегля/интервала и отказ при неоднозначности. Runner отклоняет устаревший neutral input до API и не продолжает серию с изменёнными настройками.

Синтетический transfer использует два абзаца с новым текстом и намеренно неправильной типографикой. Роли заданы fixture, модель не вызывается. Это проверка преобразования, а не качество классификации на новой реальной статье. Она не заменяет independent transfer corpus.

## Ограничения результата

- I3 получил source formatting; это самостоятельный baseline, не завершение исходного исследования восстановления очищенного текста.
- Один документ уже участвовал в подготовке шаблона и настройке. Реальные unseen статьи не проверены.
- Точность относится к зафиксированному LibreOffice, шрифтам, 12 страницам и 144 DPI. Microsoft Word не проверен.
- Ресурсы styles/theme/numbering/settings должны быть совместимы. Импорт произвольных чужих ресурсов ещё не реализован.
- Шаблон и наблюдаемые правила остаются research draft. Однозначность сопоставления свойств не означает утверждение издательских требований.
- Дешёвая модель может быть лучшей среди измеренных для role-only I3, но это не определяет минимальную модель для полного выбора оформления I1/I2.

Общий бюджет считается по единому ledger с историческими расходами. Итоги расходов включают все новые попытки, а локальное время и CPU не выдаются за бесплатный API.

Фактические новые расходы API: **$0.278408285**, накопленные: **$2.787404085**. Неопределённых резервов нет; общий предел $5 соблюдён. Синтетический transfer дал content/inline/pixel exact при 0 вызовов модели, с новым текстом и действительно изменённым выходным файлом.
