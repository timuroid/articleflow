# Проверка восстановленного ArticleFlow 17 октября 2026

Текущий Web 017 сохраняет проверенное содержание и переставляет явно
подписанные части аннотации, но пока не обеспечивает точное оформление
новой статьи по шаблону. Успешная работа сайта и зелёные unit-тесты этого
свойства не доказывают. Серия 018 оценивает детерминированный код без LLM.

## Новый прогон 018

[Протокол](evaluation-018-protocol.md) был записан до измерений.
Проверены 19 файлов corpus manifest, 7 evaluation inputs (6 полных и один
с пропусками), 24 перестановки аннотации, один приватный эталон. Роли evaluator
не передавались приложению. Стиль выбирался только по двум train-образцам
каждого профиля; это алгоритмический baseline выбора конфликтов.

Исходная реализация: commit `238a0c6191bae675efcfc9eb02174f81d63baf03`.
Повторный прогон содержит только исправление ZIP-упаковки: алгоритмы ролей,
стилей и порядка не менялись. Хеши файлов реализации, evaluator, протокола,
корпуса и окружение сохранены в JSON. У baseline evaluator не записывал хеш
`docx_engine.py` отдельно: его версия определяется указанным исходным commit.
В повторном прогоне этот хеш добавлен; `code_commit` указывает базовый HEAD,
а фактически проверенный исправленный файл определяется своим SHA-256.

90.79% не означает 90.79% готовых статей: большинство блоков — body,
а в каждом документе ошибочны два блока. Продолжение ключевых слов и
завершающая редакционная заметка назначены body. Эти ошибки зафиксированы
как текущие ограничения, эвристики на evaluation-корпусе не подгонялись.
Синтетические статьи созданы одним генератором, поэтому число независимых
реальных статей в оценке переноса равно нулю.

## Визуальное качество

Оба прогона: 10/10 повторных рендеров контрольного DOCX совпали по raster hashes.
Среда: macOS arm64, LibreOfficeDev 26.8.0.0.alpha0, 144 DPI RGB.
Arial/Times New Roman найдены; fc-match сообщает подстановку Verdana для Calibri.
Это зафиксированная проверка LibreOffice, совместимость Word не измерена.

| Профиль | Страницы golden → output | Различающиеся пиксели |
| --- | --- | --- |
| north, два документа | 2 → 2 | 5.107% и 5.139% |
| east, два документа | 1 → 2 | Общая доля не считается при разном числе страниц |
| south, два документа | 2 → 2 | 2.755% и 2.747% |

Три пары north/east/south просмотрены визуально по всем их страницам:
теряются целевые жирные/курсивные заголовки, отличаются шрифт, интервалы,
ширина набора, подписи и пагинация; в конце остаётся редакционная заметка.
Таблицы, диаграммы и формулы видны. Числовое сравнение выполнено для всех
шести пар; субъективный просмотр этих трёх пар — диагностическая выборка.
Документ north дополнительно прошёл packaged `render_docx.py`.

Причины соответствуют коду: extractor читает прямые pPr/rPr, не разрешает
полностью наследование styles/theme, сборщик сохраняет секцию входа,
а bold/italic не переносит как типографику смысловой роли. Формально
styles.xml совпал в 2/6, параметры секции — в 4/6; одного такого совпадения
недостаточно для точного вида. Установка шрифтов не исправляет эти ограничения.

Приватный эталон с проверенным SHA-256 сохранён без потери payload и объектов.
Результат имеет 12 страниц, как вход. Страницы 2–12 точны, страница 1 изменилась
после перестановки блоков; общая доля отличий 1.438%. Это диагностический
прогон исходного образца без независимой разметки, не успех transfer.

## HTTP, защита и исправление

На локальном TestClient обработаны пакеты 1/20/200: все задания сохранены,
все черновики имеют валидный ZIP, exports содержат полный manifest;
final заблокирован HTTP 409, в results/ нет черновиков. После исправления
wall time: 0.14 / 2.99 / 34.58 с. Пакет 201 отклонён HTTP 400.
Время включает синхронное ожидание background tasks в TestClient;
это не измерение серверной очереди, сети или нескольких пользователей.

Первый запуск evaluator остановился на `ZIP_RATIO_OR_ENCRYPTION`: повторное
сжатие плоского PNG (38548 → 378 байт) превысило входной предел 100:1.
Остановка сохранена в закрытых артефактах; два полных прогона не скрывают её.
Evaluator получил независимое чтение ZIP, чтобы измерить содержание
отвергнутого результата и отдельно считать reimport. Затем исправлен
`write_package`: слишком сильно сжимаемые части записываются ZIP_STORED.
Байты содержимого и прежний защитный предел парсера не меняются.
Сценарий SC-086 и два теста проверяют как повторный импорт, так и сохранение
отказа для внешнего чрезмерно сжатого пакета.

Итоговая проверка: **68 unit/integration tests, 15 behave scenarios / 57 steps**.
Два полных прогона дают одинаковые payload и визуальные метрики; исправление
улучшает только совместимость выходного контейнера с собственным импортом.
Миграция БД/API не требуется; старые DOCX не переписываются автоматически.

## Что пока нельзя утверждать

- Свежих вызовов модели нет, расходы серии 018 — $0. Закрытый prompt,
  накопленный usage ledger и текущий бюджет не восстановлены. Ключ сам по
  себе не разрешает обнулить расходы и начать новую платную серию.
- Точность на независимых реальных статьях, время редактора, Word-совместимость,
  restart/resume очереди и конкурентная нагрузка в этой серии не измерены.
- На действующем сервере read-only config подтвердил отключённый LLM и
  отсутствие точных Arial/Times New Roman. Локальные 34.58 с нельзя переносить
  на сервер. Состояние установленного релиза фиксируется отдельно.

Приоритет следующей разработки: effective styles и перенос геометрии;
разделение авторских semantic spans и типографики ролей; keywords/editorial;
затем независимый размеченный корпус и модельные прогоны с восстановленным
учётом бюджета. Текущие synthetic inputs после этой диагностики — development.

## Воспроизведение и сохранение

```bash
python scripts/build_synthetic_corpus.py --verify
python scripts/benchmark_web017.py --output artifacts/evaluation-018-new --http --render
# Необязательная отдельная проверка: --private-reference /private/reference.docx
python -m unittest discover -s tests
behave docs/product/scenarios/research-pilot.feature
```

Для рендера PATH должен указывать на зафиксированный bundled soffice.
Evaluator не перезаписывает уже существующий output directory. Каждая
будущая среда получает собственный environment manifest, результаты не
приписываются старому renderer автоматически.

Публичные данные: [baseline JSON](evaluation-018-baseline.json),
[patched JSON](evaluation-018-patched.json),
[все 70 повторов после исправления](evaluation-018-attempts.csv).
Приватные DOCX/PDF/PNG и снимки стенда сохраняются отдельно с SHA-256,
без публикации исходной статьи, prompt, ключей или журнала расходов.
