# Проверка опубликованной версии 023 в новой облачной среде

Проверено 17 октября 2026 года: ветка `codex/web017-recovery`, commit
`2b3bfbe16f8bfc1e3c1b341a3025d957ae2c32da`. На момент проверки `main` оставалась
на `cd8e890`; рабочая ветка опережала её на 14 коммитов. Оценка ниже относится
к коду из GitHub, запущенному в отдельной копии. Платных вызовов, merge и
изменений production в этой проверке не было.

## Что подтверждено заново

| Проверка | Результат |

| Python unit/integration suite | 128/128, 32,043 с |
| Две реализованные BDD feature-серии | 30/30 сценариев, 119/119 шагов, 21,740 с |
| Синтаксис JavaScript | `node --check` прошёл |
| Хеши опубликованных ответов моделей | 25/25 SHA-256 совпали с manifest |
| synthetic-v1 | 19 DOCX; генерация точно повторила manifest из Git |
| complex-v023 | 12 DOCX, 2131 абзац, как в описании генератора |

| Бесплатный replay переноса | article: 10/10 страниц; nested: 16/16 страниц exact |

| Намеренно испорченные контрольные документы | 12/12 дефектов обнаружены |

Replay использовал опубликованные ответы, а не новые вызовы моделей. У всех
десяти сохранённых ответов каждого held-out семейства развёрнутые назначения
ролей совпадают; формат группирования JSON различается. Повторный рендер
выполнен для первого ответа каждого семейства. Это не дополнительные 20
fresh model trials и не двадцать новых независимых документов.

Среда: Python 3.12, LibreOfficeDev 26.8.0.0.alpha0,
python-docx 1.2.0, Pillow 12.3.0, lxml 6.1.1, PyMuPDF 1.26.6. `fc-match`
выдал **Liberation Sans вместо Arial и Liberation Serif вместо Times New Roman**.
Следовательно, новые exact результаты подтверждают равенство эталона и
кандидата в этой среде, но не воспроизведение исходного опыта с настоящими
Microsoft-шрифтами. Подмена не отменялась и не скрывалась.

Первый запуск HTTP-тестов в ограниченной песочнице завис на входе в
Starlette TestClient/AnyIO. После разрешения сетевых примитивов среды те же
тесты прошли без изменений кода. Это отдельная проблема окружения, не
измерение качества приложения. Реальные API модели в тестах не использовались.

## Существенные незакрытые задачи

1. **Перестановка смысловых блоков не включена в agent023.** Новый контракт
   возвращает одну роль на существующий абзац. `rules023.compile_plan`
   подбирает свойства, а `catalogue.render_catalogue` строит исходную
   `content.structure`. Диагностический пример с правильными известными
   ролями сохранил порядок «аннотация → название → ключевые слова» при эталоне
   «название → аннотация → ключевые слова»: конфликтов 0, unresolved 0,
   статус `rendered_unverified`, исправление порядка — false. Это не
   доказательство ложного `ready` веб-приложения: проверялся именно application
   API. Legacy `structure017` умеет перестановки и некоторые диапазоны; этот
   функционал ещё нужно согласовать с новым динамическим шаблоном.
2. **Реальный пользовательский шаблон не готов.** Сохранившаяся сводка 023
   сообщает 161/161 ролей, но неоднозначные правила; поздний offline разбор —
   47 конфликтных групп и 255 unresolved. В этой среде нет частного DOCX и
   первичных ответов для него, поэтому именно этот результат повторно не проверен.
3. **Ограничения Word остаются существенными.** Три публичных DOCX в серии023
   остановлены импортёром. Колонтитулы, поля, плавающие объекты, несколько
   секций и несовместимые ресурсы эталонов ограничивают реальный сценарий.
4. **Исследование пока малое.** Успех 20/20 в прежнем отчёте — повторы двух
   синтетических документов знакомых семейств. Нет независимой выборки
   журналов, полноценного сравнения малых моделей, локального inference
   и абляции вклада обратной связи. Архитектура и прозрачные отказы являются
   полезной основой статьи; универсальную точность по ним утверждать нельзя.

Диагностика порядка сохранена как [probe_agent023_order.py](../../scripts/probe_agent023_order.py):

```bash
python scripts/probe_agent023_order.py --output artifacts/order-probe
```

Она использует известные роли без провайдера и фиксирует фактическое поведение;
это не benchmark модели и не подмена пользовательской задачи более лёгкой.

## GitHub CI

Последний проверенный [запуск до аудита](https://github.com/timuroid/articleflow/actions/runs/39042508063)
завершился шестью падениями и одной ошибкой из 128 тестов. Генерация корпуса
прошла. В workflow отсутствовала установка LibreOffice; тесты визуального
контроля запрашивают `soffice --version` и реальный рендер, даже когда часть
проверок замокана. В этой среде с движком полный suite прошёл.

В рамках аудита workflow закреплён на Ubuntu 24.04, добавлены LibreOffice,
Fontconfig и Liberation, две исполняемые BDD-серии и бесплатный replay.
Успех нового удалённого CI нужно читать по фактическому workflow run, а не
выводить из локального успеха. CI с Liberation остаётся регрессией, не
сертификацией оригинальных Microsoft-шрифтов.

## Продолжение работы

Код, синтетические данные, сохранённые ответы и рукопись теперь достаточны для
разработки здесь. Работа должна продолжаться с этой ветки; перенос в `main`
является отдельным действием. Реальные эксперименты требуют приватного
эталона по ранее известному SHA-256, настоящих шрифтов и доступа к единственному
активному ledger; новый пустой бюджет не создаётся.

Ближайший технический шаг: определить единый контракт порядка/диапазонов для
agent023, покрыть его переставленными и смешанными смысловыми блоками, затем
разбирать реальные конфликты и расширять независимый корпус. Историческую
серию023 сохранить неизменной, новые модельные измерения вести отдельно.
