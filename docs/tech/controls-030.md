# Расширение представления DOCX 029–030

## Сохранение управляющих элементов

Версия 029 добавляет атом `control`: ручные разрывы строки/страницы/колонки и
символы `w:sym`. Программная валидация допускает только известные XML-элементы
и атрибуты. Тип разрыва, шрифт и код символа не теряются при пересборке.
Символ представлен в линейном внутреннем тексте одним U+FFFC; в итоговый DOCX
возвращается исходный XML символа. U+FFFC не печатается как текст.

Версия 030 расширяет этот механизм маркерами сложных полей `fldChar` и
`instrText`. Они также имеют один внутренний индекс, позволяющий сохранять
оформление их runs через общий план диапазонов. Это служебная линейная
репрезентация, не утверждение, что маркер — видимый символ документа.
Инструкция поля хранится в содержимом, не генерируется моделью. Предикат
`field_control` различает начало, инструкцию, разделитель и конец поля при
выборе свойств runs; целевые свойства этим предикатом не раскрываются.

## Поля и безопасность

Перед рендерингом проверяются сбалансированность begin/separate/end и команды.
Разрешены только PAGE, NUMPAGES, PAGEREF, REF, TOC, TITLE. INCLUDETEXT,
INCLUDEPICTURE, DDE/DDEAUTO и неизвестные команды отклоняются. Проверка повторяется
после сборки, до записи результата. Вложенные поля результата допустимы;
инструкция вне поля и незакрытое поле — ошибки. Новые команды требуют отдельного
расширения и тестов, не разрешаются автоматически по ответу LLM.

## Контейнеры и рисунки

Блочные `sdt`/`sdtContent` добавлены в структурное дерево и проверку топологии.
Свойства контейнера сохраняются в каталоге. Это нужно, в частности, для оглавлений
и полей в колонтитулах. Плавающий рисунок `wp:anchor` сохраняется общим механизмом
drawing rules с отделёнными resource bindings. Текстовые поля `txbxContent`
по-прежнему отклоняются: разрешение anchor не означает поддержку текста внутри
произвольной фигуры. Изменение геометрии рисунков пока не входит в программу
стресс-повреждений.

## Совместимость и границы

Расширения добавляют типы атомов/контейнеров к каталогу; старые runtime должны
отклонять неизвестные типы. Пакеты со сложными полями нужно извлечь заново:
линейные координаты включают служебные маркеры, старые планы несовместимы по
hash содержимого. Нельзя присвоить новую версию старому плану вручную.

Реконструкция 19- и 22-страничных регламентов прошла сравнение всех страниц
и инвариантов в одной среде. Это подтверждает импорт/сборку экземпляра, а не
успешное извлечение переносимых правил. Модельная серия 030 измеряется отдельно.
Дополнительно исправлен порядок preflight: проверка безопасного DOCX-контейнера
и полей выполняется до запуска LibreOffice.
