# Полный визуальный контроль и извлечение 022

Требования: PRD-002, PRD-005, PRD-007, PRD-026, PRD-027, PRD-028.

## Два независимых результата

`template-agent-022` отдельно проверяет полноту каталога свойств и **повторную
сборку эталона рабочим форматировщиком**. Допуск зависит от обоих результатов.
`document-loop-022` проверяет **физические дефекты страниц новой статьи**.
Ни один из этих результатов не является измерением правильности назначения
смысловых ролей моделью на независимых рукописях.

Обнаруженная причина потерь: Web 019–021 сводил роль к одному набору pPr/rPr.
Даже все варианты такого профиля не сохраняют все изменения внутри строки,
свойства знака абзаца и каждой ячейки. Исследовательский каталог 0.4 уже хранит
эти свойства отдельно. 022 подключает его к веб-процессу и автоматическому
эксперименту, не выдавая этот старый алгоритм за новую модель.

## Локальный агентный цикл

После загрузки DOCX сервер создаёт фоновый `template_run` и выполняет:

1. Проверку контейнера, матрицы поддержки, количества блоков и источников.
2. Рендер эталона в отдельном каталоге. Все страницы являются golden только
   для оценщика; содержимое остаётся приватным.
3. Гипотезу компактных профилей: применить **каждый наблюдённый вариант** к
   соответствующему исходному блоку, отрендерить весь документ, сравнить.
4. Расширение представления до полного каталога свойств paragraph, character,
   table, row, cell, section, drawing. Полный каталог создаётся и при успехе
   компактной гипотезы, чтобы сведения о вариантах не потерялись.
5. Сборку document.xml заново из content, resources и отдельного контрольного
   плана. Сборщик не читает исходный DOCX. Контрольный план содержит исходные
   назначения и **не входит в переносимый шаблон**.
6. Независимое сравнение содержимого и позиций объектов; рендер; сравнение
   числа, размеров и **всех пикселей всех страниц** при 144 DPI RGB.
7. Отрицательные опыты: изменённый шрифт, геометрия страницы и удаление
   отступа после таблицы (если он есть) должны обнаруживаться. Для каждой
   страницы сохраняются hashes и карта различий.
8. Повторную сборку выбранными рабочими профилями на исходном и очищенном
   входе. Критерий допуска описан ниже; успех каталога его не заменяет.

Это ограниченный локальный tool-agent с двумя стратегиями представления,
без новых LLM-вызовов и без платного цикла repairs. Семантический анализ
моделью остаётся отдельной существующей операцией с согласием и ledger.
Успех — точное воспроизведение поддерживаемого образца, не I1 и не unseen
transfer. Условия выбора между наблюдёнными вариантами не выводятся из
простого факта их наличия.

Пределы: 1–10 DOCX, 2000 абзацев с ячейками на файл, 100 страниц на файл,
две стратегии и 600 секунд между этапами; отдельный render ограничен 90 с.
После исчерпания гипотез, неподдерживаемого элемента или невозможности
рендера цикл сохраняет причину и останавливается. Он не снижает допуск,
не скрывает ошибки, не переписывает научный текст и не просит пользователя
отменить техническую проверку. Сложная норма остаётся `needs_review`.
Много секций, колонтитулы, notes/comments с текстом, поля, floating drawings,
tracked changes и другие неподдерживаемые конструкции пока не принимаются
как проверенный универсальный шаблон. «Любой DOCX» — целевое направление,
а не обещание текущего покрытия Word.

## Переносимый пакет и применение

Приватный скачиваемый ZIP содержит только `rules.json` и `resources.zip` для
каждого образца плюс manifest. В нём нет текста content, media, source DOCX,
контрольного плана или рендеров. Ресурсы могут содержать метаданные стилей и
лицензируемые шрифты; ZIP не предназначен для автоматической публикации.

Web-применение к новой статье пока использует компактные профили. Если
рабочая повторная сборка не совпала с эталоном, новую версию утвердить нельзя.
Применение старых версий без нового контракта допуска остаётся draft.
Полный каталог не даёт обхода этого ограничения. Перенос всех его вариантов
через модельный DocumentPlan на независимые статьи — отдельный следующий
этап. При единственном лидере частоты UI предлагает вариант; ничьи остаются
невыбранными. Частота — рекомендация, не доказательство нормы журнала.

## Проверка нового результата

Каждая новая веб-ревизия рендерится, PDF доступен по защищённому API.
Проверяются все страницы: выход текста/изображений за страницу, значительные
пересечения текстовых строк, отсутствующие glyphs, пустые страницы, отдельные
заголовки/подписи внизу страницы. Для коротких таблиц (до 6 строк, менее 1500
символов) проверяется разрыв по найденным уникальным текстам ячеек.
Неоднозначные/короткие строки не используются для привязки таблицы.

Разрешён один ремонт: keepNext для обнаруженной подписи/заголовка либо
короткой таблицы с подписью. Научная сигнатура должна остаться прежней.
Изменение принимается только после повторного рендера и сокращения числа
замечаний. Это эвристические физические проверки, не полное доказательство
верстки: пересечения произвольной векторной графики, нормы журнала и Word
пока не проверяются. Незавершённая проверка блокирует ready.

## HTTP и хранение

- `POST /templates` автоматически ставит извлечение в очередь, возвращает
  `extraction_run_id` вместе с прежними полями ответа.
- `POST /templates/{id}/refine` — новый ограниченный эксперимент.
- `GET /templates/{id}/runs`, `GET /template-runs/{run_id}` — история/этапы.
- `GET /template-runs/{run_id}/preview/{sample_index}` — PDF восстановления.
- `GET /template-runs/{run_id}/catalogue` — только проверенный полный каталог.
- `POST /templates/{id}/approve` — прежний gate интервалов плюс полный успешный
  цикл для конкретных selected/required; выполняется заново. Ошибка: HTTP 409.
- `GET /jobs/{id}/preview` — PDF текущей ревизии. ZIP как прежде содержит только
  ready DOCX; draft не становится готовым из-за существования PDF.

Все пути под `/api/v017`. Mutations требуют CSRF; внешний доступ защищён
существующим HTTPS Basic Auth. Таблица `template_runs` добавляется без
изменения старых версий. После рестарта queued/running отмечаются interrupted.
Операции сериализованы общим worker lock; текущий сервер одно-процессный.
Старые версии не получают проверку 022 задним числом; нужно переизвлечение.
Канонического технического PDF у проекта нет.

## Обязательный допуск рабочего шаблона (уточнение 022-v1)

После замечания пользователя об интервале после таблицы обнаружена ошибка
критерия допуска: успешная реконструкция полным каталогом не проверяла тот
сборщик, который реально используется для статей. Теперь этот результат
показывается отдельно и никогда не разрешает утверждение сам по себе.

Каждый цикл дополнительно вызывает **production `compile_document`** дважды:
на исходном эталоне и на его копии без абзацной/символьной типографики, пустых
абзацев оформления и геометрии таблиц. Семантические роли заданы оценщиком,
чтобы ошибки модели не скрывали ошибки сборщика. Сохраняются научные объекты,
выделения и связи; исходная геометрия изображений пока остаётся объявленным
входом этого контроля. Это не тест восстановления рисунков из plain text.
Нельзя передать голый текст и проверить сохранность таблиц/формул: структура
этих объектов должна присутствовать во входном представлении.

Выбранные профили должны восстановить **все страницы обоих входов** с нулевой
разницей пикселей, без недостающих блоков и нерешённых вопросов сборщика.
Иначе весь запуск `needs_review`, даже при 12/12 точных страницах каталога.
Approval каждый раз проверяет конкретный набор selected и required. Запуски
старого контракта и другого выбора не переиспользуются. Успешный результат
имеет `acceptance_contract=production-roundtrip-022-v1`.

Пустые абзацы сразу после таблицы извлекаются в `trailing_spacing` конкретного
варианта таблицы. При применении существующие пустые абзацы переиспользуются,
новые вставляются с provenance `table_spacing`. Для другого наблюдения без
пустого абзаца правило остаётся пустым. Более трёх строк или лишние исходные
строки требуют проверки, ничего не удаляется молча. Отдельный контроль
сравнивает одинаковый синтетический текст с исходным и извлечённым интервалом;
удаление интервала должно обнаруживаться. Полный отрицательный опыт также
убирает один реальный пустой абзац после таблицы, если он есть в эталоне.

Это устраняет ложный допуск, но не устраняет автоматически неполноту рабочих
компактных профилей. Реальный эталон должен оставаться неутверждённым, пока
рабочий сборщик не воспроизводит его; изменение статуса на passed вручную
или замена рабочего контроля каталогом запрещены.

`GET /template-runs/{id}/comparison/{sample_index}/{mode}` предоставляет
приватные PDF reference/original/neutralized для диагностики провала.
CLI `scripts/verify_visual022.py --selection selection.json` проверяет
конкретный набор выбранных профилей. При `refine` старой ревизии извлекателя
создаётся новая неутверждённая версия из исходных файлов; старые остаются.
