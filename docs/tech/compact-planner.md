# Компактный план модели 0.5

Требования: PRD-005, PRD-007, PRD-013–PRD-015. Этот исследовательский профиль соединяет выбор модели с [каталогом и сборщиком 0.4](catalogue-renderer.md). Успех renderer с source oracle не считается результатом модели. Первый запуск — диагностический; серия из десяти требует замороженных входов, prompt и параметров.

## Что получает модель

Роли с описаниями, допустимые варианты, компактные идентификаторы свойств, полные XML-свойства в JSON-деревьях и связанные определения стилей. Модель также получает неизменяемый текст всех блоков, порядок и структуру таблиц, позиции формул/рисунков/гиперссылок. Исходные назначения paragraph/character styles, oracle-план, исходный DOCX и golden PDF в prompt не попадают. Генератор model input вообще не принимает пути к oracle и golden.

Короткие aliases `p1`, `c1`, `t1`, `r1`, `x1`, `s1`, `d1` назначаются сортировкой hashes, а не порядком употребления стилей в образце. Они обозначают соответственно paragraph, character, table, row, cell, section и drawing. Модель выбирает вариант по описанным свойствам; код не подставляет наиболее частый вариант по роли.

Это каталог наблюдений, а не утверждённые редактором условия применения. Из обычного текста могут быть невыводимы ручные различия кернинга, языка или пустых абзацев. Эксперимент измеряет это ограничение отдельно от точности сборщика. Opaque OMML сохраняется при сборке; профиль не называется строгим I1.

## Что возвращает модель

Для каждого блока: `id`, `role`, `paragraph`, `character`, `marks`. `character` задаёт базовый вариант для всего текста; null допускается только у пустого блока. Каждый mark задаёт точную подстроку `text`, её вхождение `occurrence` (с единицы, включая перекрывающиеся вхождения) и полный character style alias. Нормализация пробелов, регистра, Unicode и нечёткий поиск запрещены. Пересечение marks отклоняется. Замены текста нет: цитата служит только адресом существующего диапазона.

Для каждого table/row/cell узла модель возвращает `id, style`; для каждого рисунка — `id, drawing, character`; для документа — `section`. Все элементы должны быть покрыты ровно один раз. Компилятор переводит aliases и цитаты в план `catalogue-0.4`, выставляет provenance `model_compact`, проверяет совместимость роли и свойств, затем вызывает прежний renderer. Отсутствующий выбор не заполняется из oracle.

## Валидация и исследование

JSON Schema запрещает неизвестные поля и aliases. Далее проверяются IDs, цитаты, диапазоны и совместимость с ролью. Любая ошибка завершает one-pass попытку без repair. Приватно сохраняются исходный ответ и compiled plan, hashes prompt/schema/template/input, usage и все ошибки. Реальный scientific text и ответы не публикуются в Git.

После ответа evaluator отдельно читает oracle и golden. Измеряются роли, paragraph style selection, character style selection по code points, layout/object/section selection, сохранность содержимого, расположение объектов и exact pixels. Равенство style IDs — диагностическая метрика; два разных набора свойств могут дать одинаковые пиксели. Строгий gate по полному документу не заменяется средним процентом.

Каждая попытка использует общий ledger `artifacts/pilot-001/trials/usage-ledger.json`; предел $5 включает ранее потраченные $1.5405222 и неопределённые резервы. Только модели после 2026-06-30, проверенный тариф и один HTTP POST на попытку. Уменьшение модели допускается после прохождения quality gate. Обычные тесты API не вызывают.

## Команды

```bash
articleflow planner-input artifacts/catalogue-004/template artifacts/catalogue-004/content artifacts/planner-input.json
articleflow compile-plan artifacts/catalogue-004/template artifacts/catalogue-004/content artifacts/response.json artifacts/compiled-plan.json
articleflow render-catalogue artifacts/catalogue-004/template artifacts/catalogue-004/content artifacts/compiled-plan.json artifacts/candidate.docx
```

`catalogue-trials --help` описывает платный runner. Все девять путей задаются явно: template, content, oracle, source, golden PDF, сохранённый каталог OpenRouter, registry, output и существующий общий ledger. По умолчанию одна попытка, GPT-6.1 Sol, reasoning medium, output cap 24000 токенов. `--first` и `--repeats` продолжают серию; изменение prompt/schema/model/тарифа в существующей папке запрещено. HTTP retry отсутствует. При неизвестной стоимости runner останавливается и оставляет резерв. Запускать runner последовательно: конкурентное резервирование бюджета ещё не реализовано.

Начальная диагностическая схема допускала любые character aliases и проверяла совместимость с ролью после ответа. Рабочая схема связывает роли и допустимые свойства через вложенный `anyOf`. Это ограничивает форму ответа, но не доказывает правильность смыслового выбора. Разные схемы имеют разные hashes и отдельные серии.

Продолжение серии проверяет смысловое равенство model view и использует сохранённый порядок JSON-ключей первого запроса. Повторное использование входа не является кэшированием ответа модели. Варианты стилей сортируются при построении новых запросов, поэтому Python hash randomization не меняет prompt.

Резерв на запрос использует верхнюю оценку входных токенов по UTF-8 bytes и максимальный входной тариф среди обычного input, cache read и cache write. Предполагаемые cache hits не уменьшают резерв. Тарифы с длинным контекстом отклоняются, если верхняя оценка достигает первой ценовой границы; отдельный tier-aware адаптер пока не реализован.
