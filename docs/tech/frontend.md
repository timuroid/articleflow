# Frontend

## Стек и модули

Предложение: React + TypeScript + Vite, router, TanStack Query для server state, библиотека валидируемых форм и доступные UI primitives. Конкретные версии фиксируются в lockfile при реализации. Клиент строится по [спецификации интерфейса](../product/interface.md).

Feature-модули: templates, documents/upload, jobs/review, results, settings. Общие компоненты: FilePicker, JobStageList, RuleEditor, EvidencePanel, ReviewQuestion, FindingsTable, DownloadButton. UI-типам нельзя самостоятельно придумывать enum статусов; они генерируются/проверяются по API-схеме.

## Состояние

Backend — источник истины о job, approved template и правах. В React state живут открытые вкладки, фильтры и ещё не отправленные значения формы. Query keys включают workspace ID и entity ID; при смене пространства данные предыдущего не отображаются. Текст рукописи и ключи не сохраняются в localStorage/analytics.

Job polling: начально каждые 2 s, при длительном ожидании до 10 s, с backoff на сетевых ошибках. На терминальном состоянии polling останавливается; при возврате вкладки выполняется refetch. Progress не выводится из прошедшего времени. events endpoint используется для восстановления списка событий по sequence; SSE можно добавить позднее.

## Формы и команды

Idempotency key создаётся один раз на пользовательское намерение и переиспользуется при retry HTTP. Новый сознательный запуск получает новый key. Disable кнопки предотвращает случайное двойное нажатие, но серверная идемпотентность остаётся обязательной.

Редактор правил отправляет expected revision/If-Match. При `409` получает свежую версию и показывает конфликт; автоматическая перезапись не выполняется. Review отправляет только option IDs текущей revision. После accepted ответа инвалидируются job/review queries; optimistic UI не должен изображать successful formatting до ответа worker.

## Просмотр документа

Preview строится из безопасного IR: текст экранируется, XML не вставляется через innerHTML, внешние изображения не подгружаются. Hyperlinks отображаются как данные; открытие внешнего адреса — явное действие пользователя с безопасными атрибутами. Виртуализация не меняет block IDs, чтобы findings и evidence открывали правильный фрагмент.

Для интерфейса таблиц/формул на первом этапе допустимо обозначение объекта с метаданными и переходом к исходнику; нельзя выдавать заглушку за полноценную визуализацию. Критерий сохранности определяется backend, не браузерным render.

## Ошибки и доступность

Различать transport error и failed job. На 401 восстановить сессию; на 404 показать недоступность ресурса без раскрытия чужого имени. Form errors связаны с полями, error summary получает фокус. Вопросы имеют текстовые labels, уведомления не исчезают раньше чтения, действия доступны без drag-and-drop. Frontend tests проверяют полный путь загрузки/review/download и stale revision, а не внутреннее устройство компонентов.

## Пакеты и выделения v0.2

Добавляются modules batches/exports и редактор character rules. Multi-file upload ограничивает параллельность (предложение 3 uploads), хранит item IDs и не держит в памяти все bytes сотен DOCX. Server state восстанавливается по batch ID; client pending file handles после перезагрузки могут потребовать повторного выбора только незагруженных файлов.

Batch rows виртуализированы, показывают реальные states каждого item и счётчики сервера. Download ZIP создаёт async export с partial flag; повторное нажатие использует тот же idempotency key. UI не обещает готовность архива по завершению только одного job. Для term spans UI переводит Unicode code point offsets в UTF-16/DOM positions; изменение отображения не меняет исходную строку.
