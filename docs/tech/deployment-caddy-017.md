# Развёртывание восстановленного Web 017 за Caddy

Эта процедура относится к **новой реализации** `codex/web017-recovery`, а не к исчезнувшему архиву с историческим SHA-256. Сначала сверить commit, запустить тесты и собрать исходный релиз из чистого Git-дерева: `python3 scripts/package-web017.py artifacts/releases/articleflow-web-017.tar.gz`. Повторно проверить архив `python3 scripts/audit_web_release.py artifacts/releases/articleflow-web-017.tar.gz`. Упаковщик берёт только исходники, тесты, скрипты, документацию и разрешённые корневые файлы: исследовательский `datasets/` остаётся в Git, но не входит в серверный релиз. Не включать в него `private-fixtures/`, `artifacts/`, `.env`, реальные статьи, prompt и ledger.

Перед установкой проверить ОС, свободное место, текущие Caddy site blocks, порты 80/443/8769 и DNS. На рассматриваемом сервере 80/443 уже принадлежат Caddy, поэтому nginx/certbot не ставить и Caddyfile не заменять. Архив передать по SSH в закрытый путь сервера, распаковать в отдельный временный каталог и выполнить `scripts/install-web017.sh /path/to/articleflow-web-017.tar.gz` из этой копии. Скрипт проверяет состав архива, создаёт отдельный systemd-сервис `articleflow`, приватную папку `/var/lib/articleflow` и запускает FastAPI только на `127.0.0.1:8769`. Если сервис или путь уже существуют, он останавливается для ручной проверки; существующие сайты не меняет.

После `curl --fail http://127.0.0.1:8769/healthz` выполнить `scripts/enable-https017.sh <домен>` от root. Скрипт создаёт отдельный site-файл `/etc/caddy/articleflow.caddy`, добавляет один `import` в существующий Caddyfile, делает резервную копию Caddyfile, проверяет конфигурацию и перезагружает Caddy. Пароль HTTP Basic Auth генерируется случайно и сохраняется только в `/root/articleflow-http-password` с правами 0600; в скрипт, URL, Git или логи он не вставляется. Caddy выпускает и обновляет сертификат штатно. При ошибке проверки или reload Caddyfile восстанавливается. Пароль владелец читает через свой SSH-доступ.

Приёмка: `systemctl is-active articleflow caddy`, `caddy validate --config /etc/caddy/Caddyfile`, запрос без логина через HTTPS даёт 401, сертификат валиден, после входа открывается UI. Проверить один разрешённый DOCX, скачивание черновика и отчёта, ручное утверждение ролей, пакет из двух файлов и ZIP с manifest. Незаполненные обязательные части блокируют `final` и включение файла в `results/`. На сервере проверить `fc-match` для **точных** Arial и Times New Roman; fallback Liberation не считается подтверждением. Если шрифтов нет, статус оформления остаётся `draft`.

Отдельно создать приватную резервную копию `/var/lib/articleflow` с SQLite и файлами, проверить восстановление из неё. Эта инструкция не подключает OpenRouter: для него сначала нужны новый действующий ключ, закрытый prompt, прежний usage ledger, подтверждённый лимит и отдельное согласование отправки реальных статей провайдеру. Успешный локальный Web 017 не подтверждает точность модели.
