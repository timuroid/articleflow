# Проверки результата и отчёт

## Уровни проверки

| Уровень | Что проверяется | Последствие ошибки |
| --- | --- | --- |
| Package | ZIP, OPC parts, content types, internal relationships, XML namespaces | Blocker, DOCX не выдаётся |
| Content | Текст, формулы, media, таблицы, заметки, ссылки и semantic inline markers | Blocker, DOCX не выдаётся |
| Structure | Полнота block mapping, роли, обязательность, порядок, зависимости | Review до рендера или blocker после |
| Formatting | Эффективные свойства согласно rule IDs | Обязательное правило → blocker; необязательное → warning |
| Visual | Шрифты, переносы, переполнение, пагинация | Проверено конкретным движком либо явно unchecked |

`blocker`, `warning`, `info` — severity отдельных findings. Статус проверки `passed`, `failed` или `unchecked` не совпадает с severity. Непроверенное обязательное правило нельзя считать пройденным; оно блокирует выпуск. Непроверенная необязательная визуальная характеристика даёт warning.

## Контракт сохранности

До рендера фиксируется baseline по каждому блоку и объекту. После рендера исходные IDs сопоставляются с output locations через mapping. Для текста сравнивается точная последовательность Unicode после только документированных структурных преобразований XML: объединения последовательных `w:t` в рамках того же логического span и декодирования XML entities. Не удалять пробелы, не нормализовать дефисы, Unicode, знаки минуса и десятичные разделители ради прохождения проверки.

Сравнение включает main document, таблицы по координатам, footnotes/endnotes, поддерживаемые headers/footers и comments. Даже если документ содержит то же множество слов, изменение порядка или перенос числа в другую ячейку является нарушением. При разрешённой перестановке сравниваются payload каждого перемещённого блока и явно утверждённая перестановка, а не общий конкатенированный текст.

Формулы сравниваются по каноническому OMML-поддереву; бинарные изображения — по SHA-256; таблицы — по структуре объединений и содержимому ячеек; ссылки — по URI/anchor и текстовому диапазону; поля — по instruction text и зависимостям. Счётчики объектов применяются как ранний сигнал, но не заменяют содержательное сравнение.

Новые пустые служебные абзацы, изменение полей Word и другие исключения допускаются только как отдельные allowlisted операции с fixture и явным контрактом. Не добавлять широкое правило «игнорировать всё форматирование»: часть run properties несёт смысл.

В v0.2 `insert_approved_label` добавляет только literal из подтверждённой версии в определённый slot. Validator отдельно сопоставляет original scientific payload и generated template content, проверяет строку literal, позицию и отсутствие дубля. Подмена научного текста этим исключением запрещена. Применение нового term style сравнивается с semantic rule/golden spans, сохранение исходного meaningful emphasis — с input contract. Plain text не даёт права объявлять неизвестные исходные emphasis восстановленными.

## Проверка оформления

Сравнивается effective style после наследования, а не наличие style ID. Стиль может быть назначен правильно, но перекрыт прямым кеглем. Проверить размер страницы/поля, шрифты по script, paragraph spacing/indent/alignment, заданные keep properties, ширины объектов и номерную схему по подтверждённым правилам.

Численные значения сравниваются после единоразового преобразования в нативные целые единицы OOXML. Если правило допускает диапазон, диапазон должен быть частью TemplateSpec, а не скрытой погрешностью validator.

## Отчёт

Отчёт содержит job ID, input/output hashes, template version, tool versions, summary, applied operations, findings и integrity checks. Finding: `code`, `severity`, `check_status`, `block_ids`, `rule_id`, человекочитаемое сообщение и рекомендуемый следующий шаг. Machine consumers опираются на code, а не русский текст.

Примеры кодов: `CONTENT_TEXT_CHANGED`, `MEDIA_MISSING`, `RELATIONSHIP_BROKEN`, `REQUIRED_ROLE_MISSING`, `FORMAT_RULE_MISMATCH`, `FONT_UNAVAILABLE`, `FIELD_RESULT_UNCHECKED`, `VISUAL_LAYOUT_UNCHECKED`. Пример JSON — [report.example.json](contracts/report.example.json).

Публичный отчёт не содержит секретов и лишних фрагментов чужого образца. Для объяснения допустимы короткие фрагменты текущей статьи в авторизованном UI, но не в системном логе. Отчёт доступен даже при failed job; повреждённый DOCX не получает download capability.

## Решение о выпуске

`completed`: обязательные проверки passed, warnings отсутствуют. `completed_with_warnings`: обязательные проверки passed, есть предупреждения, в том числе визуальные unchecked. `failed`: хотя бы один blocker после выполнения или невосстановимая техническая ошибка. `needs_review`: вопрос можно решить до безопасного выполнения/повторной валидации. Нельзя перевести результат с нарушением content integrity в completed кнопкой «принять риск».

## Визуальный benchmark v0.2

Исследование дополнительно выполняет [pixel protocol](../research/benchmark.md): golden и output рендерятся одним фиксированным engine/font/DPI profile; exact означает ноль отличающихся пикселей и равные страницы/canvas. SSIM и MAE — диагностика, не замена exact. В production неизвестен golden для новой статьи, поэтому такой тест не обещается каждому пользователю; действуют проверяемые правила и отчёт о непроверенной визуальной части.
