# Извлечение и утверждение шаблона

## Наблюдения

Из одного образца извлекается `ObservationSet`: блоки с semantic role candidates, эффективные свойства, частоты сочетаний, часть пакета и source block ID. Текст нужен для распознавания роли, но в библиотеку шаблона попадает только разрешённый preview/evidence; в итоговые статьи он не переносится.

Ключи группировки: роль + уровень заголовка + секция + script/language, если это влияет на оформление. `Heading 1` — сильный признак, но не абсолютное доказательство: исходный документ может использовать стиль неправильно. Аналогично крупный полужирный абзац может быть названием, а может быть заголовком таблицы.

## Правила и неопределённость

Для свойства сохраняются `value`, `unit`, `origin`, `evidence_block_ids`, `confirmation`. Модальное значение — кандидат; среднее между 12 и 14 pt не становится автоматически 13 pt. Повторяемость измеряется на независимых блоках, а не количестве runs одного абзаца.

Происхождение:

- `observed`: непосредственно измерено в OOXML, есть evidence.
- `inferred`: обобщено эвристикой/моделью, требует подтверждения согласно политике.
- `manual`: задано редактором, сохраняются actor/time и комментарий.

Оценка уверенности модели используется только как сигнал сортировки вопросов. До калибровки на корпусе нет единого магического порога «0.9 значит верно». Обязательные вопросы возникают при конфликтующих ролях, нескольких существенных вариантах оформления, неизвестном обязательном правиле или преобразовании вне профиля поддержки.

## Компиляция шаблона

Компилятор превращает подтверждённые правила в неизменяемый профиль. Он проверяет:

1. Поля и размеры оставляют положительную область содержимого.
2. Кегль, интервалы и отступы имеют допустимые диапазоны и единицы.
3. У каждого role ID есть однозначное правило либо явный fallback `preserve`.
4. Заголовки имеют допустимую иерархию; правила не образуют цикл наследования.
5. Обязательность разделов задана редактором, а не выведена из наличия одного примера.
6. Известные unsupported constructs не маскируются default-стилем.
7. Колонтитулы и static text не содержат научный текст/авторов образца, предназначенный для ошибочного повторного использования.

Утверждение проходит в транзакции с optimistic lock. Для повторного запроса тот же draft revision не создаёт вторую утверждённую версию. После утверждения любые изменения делаются в новом draft; старый compiled hash остаётся прежним.

## Формат профиля

`TemplateSpec` v0.2 хранит canonical paragraph/character/semantic/object/label rules и входит в [TemplatePackage](template-package.md) вместе с renderer profile и compiled resources. [template.example.json](contracts/template.example.json) показывает связанные правила term spans и captions; это иллюстрация, не полная JSON Schema. Evidence отделено от compiled student rules.

Нужен baseline «сохранить оформление неизвестного блока», но только когда блок не препятствует целевому правилу. Если его ширина несовместима с новыми полями, fallback не делает преобразование безопасным: требуется review.

## Изменения шаблона

В первом исследовательском срезе пакет готовит сильная модель/исследователь и проверяет редактор. Это позволяет сначала измерить применение. E-ONCE/E-LOOP сравниваются позже по [протоколу](../research/methods.md); дорогая подготовка считается на версию шаблона, а не на каждую статью.

Новая статья-образец создаёт новую версию наблюдений. Существующие ручные правила не перезаписываются автоматически: редактор видит diff и принимает изменения. Для MVP достаточно ручного создания нового черновика; интеллектуальное слияние нескольких образцов отложено. Привязанные jobs всегда сохраняют точный approved version ID.
