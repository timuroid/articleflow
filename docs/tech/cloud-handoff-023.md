## 2. Исходный замысел владельца

1. Пользователь даёт один или несколько эталонных Word-документов. Дополнительные
   требования возможны, но худший и основной сценарий — их нет.
2. Большая LLM извлекает структуру и правила. Она должна экспериментировать:
   удалить оформление, собрать документ заново с помощью малой модели, сравнить
   все страницы, исправить шаблон и повторить. Одного чтения OOXML недостаточно.
3. Готовый шаблон применяется многократно малой моделью. Предпочтение владельца:
   открытая Qwen около 27B с возможностью будущего локального размещения.
4. Содержание статьи неприкосновенно. Нельзя дописывать авторов, аннотацию,
   ключевые слова, числовые результаты или ссылки, чтобы пройти проверку.
5. Человеческая обратная связь обязательна как механизм, но должна включаться
   только при существенной неоднозначности. Желательна привязка вопроса к эталону.
6. Проверяются весь документ, разные интервалы, длинные тексты, таблицы и
   вложенные таблицы. Заголовки или средняя похожесть не являются достаточным gate.
7. Нужны воспроизводимые эксперименты и содержательная научная статья с рисунками,
   схемами, графиками, примерами найденных ошибок. Презентация отложена.
8. Владелец неоднократно потребовал сохранять результаты в GitHub и закрытых
   резервных копиях: предыдущая облачная рабочая среда и часть файлов были утрачены.

Желаемое «100% на любых документах» не достигнуто. Более того, восстановление
произвольного оформления из чистого текста неидентифицируемо в общем случае.
Не обещать такой результат. Задавать ограниченный класс, объявленные входные
сигналы, нулевой допуск на конечном корпусе и явные отказы на остальных случаях.

## 5. Точная граница входов и утечки эталона

- Teacher видит обучающий текст, наблюдаемые свойства и ошибки. Student получает
  только определения ролей, новое содержание и структуру.
- Семантические bold/italic/vertical/locale сохранены как объявленные данные DOCX.
  Это I2-подобный режим; не называть его plain-text I1.
- Runtime template не содержит oracle assignments. Запрещены условия по тексту,
  hash текста, source block ID, индексу абзаца и автору эталона.
- Полный каталог свойств без правила выбора не является готовым шаблоном.
- Новый текст сравнивается со своим независимым правильно оформленным golden,
  а не с PDF другой статьи. Число страниц новой статьи может быть другим.
- При конфликте одинаковых наблюдаемых признаков система останавливается;
  запрещено молча выбирать наиболее частый стиль, подменять результат эталоном,
  дописывать недостающее содержание или ослаблять pixel tolerance.
- Обычная ручная правка legacy roles не запускает agent023 повторно: HTTP 409.
  Для текста требуется новый исходник, для обязательности — отдельная версия.

## 8. Запуск в чистой облачной среде

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -e '.[web,dev,paper]'
python scripts/cloud_preflight023.py
python -m unittest discover -s tests -q
behave docs/product/scenarios/research-pilot.feature docs/product/scenarios/structure-web.feature
python scripts/build_complex023.py --output artifacts/complex023
python scripts/replay_agent023.py --output artifacts/replay023
python scripts/build_synthetic_corpus.py
python scripts/build_synthetic_corpus.py --verify
```

Проверка свежего клона именно из GitHub на commit `2b3bfbe`: **128/128 tests**.
Бесплатный replay из этого клона прошёл оба семейства: обучение
reference_verified; перенос exact на всех 10 и 16 страницах соответственно.
Новых API-вызовов — 0. Это проверка воспроизводимости в чистом checkout на
компьютере владельца, не измерение облачного окружения. Машинная сводка:
[cloud-verification-023.json](../research/cloud-verification-023.json).
Две исполняемые feature-серии: 30 сценариев / 119 шагов. Прочие исторические
feature-файлы содержат ещё 71 сценарий с undefined steps. Запуск всего каталога
не является зелёным; не скрывать и не переименовывать эти сценарии ради отчёта.

Для визуализации установить LibreOffice и настоящие Arial/Times New Roman,
зафиксировать версии и проверить fc-match + шрифты PDF. При отсутствии шрифтов
сборка может быть технически успешной, но не является точным соответствием.
Владелец ранее согласился с EULA Microsoft Core Fonts для серверной установки;
сам cloud agent должен соблюдать применимые правила своей среды.
`ARTICLEFLOW_SOFFICE` задаёт путь soffice, `ARTICLEFLOW_FONTCONFIG` — Fontconfig.
Не копировать абсолютные macOS paths владельца в облачную конфигурацию.

```bash
ARTICLEFLOW_DATA_DIR="$PWD/artifacts/local-web" \
  uvicorn articleflow.web017:create_app --factory --host 127.0.0.1 --port 8769
```

Без ARTICLEFLOW_MODEL_CONFIG интерфейс работает локально, paid learning
недоступен. Это правильное безопасное состояние, не повод создавать пустой ledger.
Для публичного доступа обязательны reverse proxy, HTTPS и вход. Открытый
backend не выставлять наружу.

## 9. Платные эксперименты и ключи

Активный ledger находится на сервере владельца, `/var/lib/articleflow/config019/ledger.json`.
Копии на ноутбуке read_only. В 019 baseline usage=7.956670174, cap был3USD;
по последнему запросу владельца cap повышен до4USD, событие сохранено в budget_changes.
Нельзя обнулять baseline, прежние attempts или неопределённые резервы.
Текущий баланс проверить заново, не переносить исторические $4 как факт.

Teacher: openai/gpt-6.1-sol, reasoning low. Reasoning none для него дал HTTP400.
Student: qwen/qwen3.8-27b, reasoning none. Не заменять модель молча. Даты выпуска
и первичные источники — ../research/models.json. Модель не развёрнута локально.

Private config содержит только пути: key_file, ledger, model, prompt_file и
прежние параметры019; точные обязательные поля читать в model019.py/model_config.
В 023 provider используются key_file, ledger, model, reasoning_effort. Секрет
передаётся через защищённые механизмы среды и не появляется в output. Каждый
новый POST проверяет provider account и резервирует максимум до отправки.
Не включать реальные модельные вызовы в CI или стандартные unit tests.

Облачная и серверная среды не должны независимо тратить один бюджет по двум
копиям ledger. Для платных запусков использовать действующий серверный worker
либо согласованную миграцию единственного writer. Ошибки/HTTP429 сохранять,
не повторять скрыто. Изменение prompt/config или ручная правка начинает новую серию.

## 14. Критерий завершения очередного шага

Код + сценарии + техническая документация + честные метрики + визуальная проверка
+ атомарный commit + push рабочей ветки + чтение remote SHA. Частные первичные
материалы — независимые копии с проверенными hashes. Не заканчивать формулировкой
«всё восстановлено», если сохранились только описания или исчезли исходные байты.
