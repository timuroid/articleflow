# Сохранение исследовательских данных и восстановление

Рабочая папка облачного исполнителя временная. Завершённый локальный результат считается сохранённым только после записи в долговременное хранилище, проверки чтения оттуда и фиксации версии. История обсуждения, путь в `/tmp` и запись о SHA-256 не восстанавливают сами байты файла.

## Классы данных

| Данные | Долговременное место | Публичный репозиторий |
| --- | --- | --- |
| Код, тесты, спецификации, рукопись **без закрытого текста**, сводные обезличенные результаты | Git, конкретный commit | Да |
| Созданные нами синтетические DOCX и manifest | Генератор и manifest в Git; DOCX локально или в разрешённом хранилище с контрольными суммами | Генератор и manifest; публикация DOCX отклонена автоматической проверкой |
| Чужие научные статьи, пользовательские эталоны и сформированные из них DOCX | Закрытое хранилище проекта с доступом владельца; индекс, источник, права и SHA-256 в приватном manifest | Нет без проверки прав и явного решения владельца |
| Исходный текст частной рукописи, полные ответы LLM, raw prompts и usage ledger | Закрытое хранилище проекта, шифрованный архив/резервная копия | Нет |
| API-ключи, пароли, `.env` | Менеджер секретов / переменные окружения | Никогда |
| Сборка релиза | Исходный код и воспроизводимый рецепт в Git; проверенный архив дополнительно в закрытом или разрешённом хранилище | Публиковать только очищенный релиз |

Закрытое долговременное хранилище для прежних пользовательских материалов **пока не подтверждено**. Не называть каталог `artifacts/` или `private-fixtures/` резервной копией: оба игнорируются Git и могут исчезнуть при замене среды. Пока закрытая копия не существует, сообщать владельцу о риске и не удалять оригинал.

## Правило завершения рабочего этапа

1. После реализации или эксперимента обновить исходники, документацию, машинный manifest и таблицу всех попыток, включая отказы. Версию модели, набор входов, параметры, дату, цены, код и renderer привязать к commit/хешам. Не переписывать предыдущую серию новым экспериментом.
2. Положить разрешённые публичные артефакты в Git, проверить `git status`, запустить локальные проверки, отправить commit в удалённый репозиторий и **прочитать его с удалённого хранилища**. Локальный commit без push недостаточен. Для синтетического корпуса проверять, что повторная сборка совпадает с manifest из Git.
3. Для закрытого набора создать отдельный приватный manifest с относительным именем, размером, SHA-256, происхождением, разрешённым использованием и ссылкой на версию backup. Сделать вторую независимую копию и выборочно открыть файлы из неё. Публичный manifest не должен раскрывать частный текст, идентификаторы авторов или секретные URL.
4. В отчёте явно различать `проверено из удалённого Git`, `проверено из закрытой копии`, `только локально`, `не найдено`. Не писать «восстановлено» для заново сгенерированного эквивалента.

Для больших разрешённых наборов предпочтительны отдельное объектное хранилище с versioning и приватный Git/LFS с проверкой прав. Конкретную площадку и владельца учётной записи нужно зафиксировать **до** следующего импорта настоящих статей. Двух копий на одном эфемерном диске недостаточно. Архив `tar.gz` полезен для передачи, но сам по себе не заменяет исходники, manifest и независимый backup.

## Как восстанавливать пропавшие данные

1. Сопоставить удалённый Git, tags/releases, ветки, Actions artifacts и доступные резервные копии со [списком отсутствующего](../../datasets/recovery-inventory.json).
2. Для каждого найденного файла проверить SHA-256 и формат; для старого эталона и архива релиза сверить ранее записанные хеши **в приватной описи**, не публикуя содержимое автоматически.
3. Импортировать код отдельно от данных; проверить, что в публичном diff нет ключей, пользовательского текста и материалов без прав на публикацию.
4. Запустить тесты и воспроизвести только те экспериментальные таблицы, для которых вернулись исходные входы, ответы, ledger и параметры. Иные записи оставить историческими сообщениями.

Новый [синтетический корпус](../../datasets/synthetic-v1/map.md) позволяет продолжить структурную разработку, но не заменяет прежнюю оценку переноса на реальные конференции. Исследовательскую рукопись, составленную заново по сохранившимся агрегатам, также нельзя считать восстановленным исходным DOCX.
