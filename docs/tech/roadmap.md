# Порядок реализации v0.2

## Этап 0. Спецификация исследования — выполнен первоначальный срез

Описаны TemplatePackage, DocumentPlan, входы, exact benchmark и пакетный продукт. Есть [первый измеренный пилот](../research/pilot-001.md); веб-приложение не реализовано.

## Этап 1. Один шаблон и измерительный стенд

Получить образец, вручную/с сильной моделью заполнить шаблон. Создать neutral input + assets, parser/renderer, oracle plan и фиксированный rasterizer. Выход: известна достаточность данных, content checks проходят, повторный рендер детерминирован. Универсальный extractor пока не нужен.

Текущее положение: один образец разобран, создан черновик с 42 ролями, проверен детерминированный рендер и lossless-контроль. Role renderer пока гибридный и не достигает exact pixels даже с oracle. Этап не закрыт; диагностические model trials не отменяют этот барьер.

## Этап 2. One-pass и лестница моделей

Сравнить G-FULL/G-PLAN/G-RULES и bounded G-LOOP, начать с сильной модели. Выполнить 10 fresh trials на конфигурацию; при прохождении gate проверить более дешёвых кандидатов. Затем проверить unseen статьи. Выход: измеренная конфигурация либо разбор недостижимого gate, без объявления победителя по одному удачному файлу.

## Этап 3. Методы извлечения

С фиксированным application method сравнить E-MANUAL/E-RULES/E-ONCE/E-LOOP и T-PROSE/T-JSON/T-BUNDLE/T-DOCX. Выход: метод подготовки переносимых правил и compiler version. Универсальный интерфейс допускает другие document profiles, но их поддержка не заявляется без проверки.

## Этап 4. Пакетный backend и web

Реализовать uploads, templates, jobs, consent, budget, outbox, очередь 100–300 элементов, individual downloads и ZIP с manifest. UI показывает правила, spans, batch progress, ошибки и режим вызовов. Выход: пакет можно обработать, повторить проблемные элементы и удалить данные без утечек через старый архив.

## Этап 5. Пилот

Измерить время редактора, cost, throughput и точность на согласованном корпусе. Проверить Word/fonts, retention, cancel/recovery и load. Применить [критерии приёмки](../product/acceptance.md), различая practical quality и exact pixels.

Расширенная вёрстка, новые document profiles и конвертация библиографии получают отдельные спецификации. Сроки и бюджет реализации оцениваются после первого корпуса и renderer baseline.
