# ADR-008: явный вход с исходными свойствами

Дата: 2026-10-15. Статус: исследовательский baseline I3; не замена исходного benchmark реконструкции I1/I2. PRD-005, PRD-013–PRD-015.

## Основание

Один и тот же очищенный текст и набор допустимых вариантов могут соответствовать разным целевым интервалам и выделениям. Добавлять номера абзацев, индивидуальные цитаты и golden assignments в переносимый шаблон нельзя. Большая модель не восстанавливает информацию, которой нет во входном контракте.

## Решение

Добавить два явно размеченных режима. Source marks сохраняют только bold/italic/vertical из входной статьи. I3 сохраняет её допустимые варианты оформления и сопоставляет неизвестную типографику только при единственном кандидате. Модель I3 назначает роли, а код выбирает свойства по [контракту](../source-aware.md). Свежие model calls, offline replay и oracle controls имеют отдельные результаты.

## Альтернативы

- Индивидуальные правила по block ID, статье или порядковому номеру дали бы подгонку под образец; отвергнуты.
- Нормализовать golden и объявить успех против изменённого эталона — другое исследование; текущий golden сохранён.
- Повторять запросы до случайного совпадения — расходует бюджет и не доказывает воспроизводимость; применяется замороженная серия с учётом всех попыток.
- Полностью копировать исходный DOCX — не проверяет применение шаблона; используется сборка нового body, а отдельный синтетический тест меняет текст и неверную типографику.

## Последствия

Точное совпадение I3 на уже оформленном образце проверяет сохранение допустимых исходных свойств, классификацию и сборку. Оно не доказывает независимое создание оформления, перенос на произвольный DOCX или минимальность модели для I1. Текущий I3 требует совместимых ресурсов styles/theme/numbering/settings и оставляет неоднозначность на review. Непрохождение исходного строгого gate остаётся явно записанным.
