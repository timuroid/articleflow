# ADR-006: выбор каталога и точные цитаты

Статус: принято для исследовательского профиля 0.5. Связи: PRD-005, PRD-007, PRD-013–PRD-015; [контракт](../compact-planner.md).

## Проблема

Полный каталог 0.4 воспроизводит образец с oracle. Прежний ответ модели «роль + bold/italic/vertical» не выбирает его варианты. Передача полных XML-свойств в ответе или повторная генерация текста увеличивает размер ответа и риск искажения содержимого. Числовые смещения требуют от модели точного подсчёта Unicode-символов.

## Решение

Модель выбирает короткие aliases полных вариантов и базовый character style для блока. Дополнительные spans адресуются точной цитатой с номером вхождения. Компилятор строит обычный план 0.4; свойства и текст берёт только из разрешённого каталога и неизменяемого входа. Роли и доступные варианты связаны JSON Schema `anyOf`; runtime validator всё равно проверяет ссылки и диапазоны.

В одной серии замораживаются смысловое содержимое и точная сериализация prompt, schema, параметры и тариф. Продолжение серии сравнивает текущий model view с сохранённым и сохраняет порядок ключей первого запроса. Встроенный provider prompt caching разрешён и отражается в usage; сохранённые ответы модели не переиспользуются. Oracle/golden читаются только evaluator после ответа.

## Альтернативы и последствия

- Полные numeric spans остаются низкоуровневым форматом renderer. Для модели точные цитаты проще, но длинные выделения могут увеличивать ответ. Несуществующая цитата — failure без fuzzy repair.
- Подстановка наиболее частого стиля по роли уменьшает ответ, но скрывает выбор и уже дала ошибки в 0.3. Сейчас каждый вариант выбирается явно.
- Передача исходных назначений дала бы точное восстановление, но подменила бы исследование предсказания; oracle в запросе запрещён.
- Каталог наблюдений без семантических условий не гарантирует определимость решения из plain text. Синтетический контроль показывает одинаковый model input при разных правильных назначениях и пикселях. Нужны условия применения либо отдельный явно обозначенный I2/I3 вход, сохраняющий научно значимую разметку.

Объём XML-описаний во входе всё ещё велик; исследование стоимости не заканчивается уменьшением ответа. Продуктовые labels, caption graph, независимые статьи и автоматическое утверждение правил остаются отдельной работой.
