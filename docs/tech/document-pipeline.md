# Сквозной алгоритм документов

## Общие входы и инварианты

Входы: неизменяемые байты DOCX, SHA-256, workspace ID, версия парсера, согласие на внешний анализ, а для статьи — ID утверждённой версии шаблона. Исходный файл никогда не модифицируется. Каждый этап пишет артефакт отдельно, фиксирует checksum и checkpoint. Работа возобновляется только при совпадении зависимостей checkpoint.

Пакет DOCX — ZIP с XML-частями, связями и двоичными объектами. Парсер должен обходить основной текст, таблицы, сноски, колонтитулы и поддерживаемые связанные части, а не только `document.paragraphs`. Каждый блок получает ID, стабильный внутри снимка исходника, например `b-000042`; ID привязан к part URI, пути узла и hash исходного фрагмента. Между разными исходниками IDs не переиспользуются как доказательство идентичности.

## Поток A: образец → шаблон

1. **Приём:** потоковая загрузка во временный объект, подсчёт размера и SHA-256, лимиты ZIP/XML, проверка content types и связей. Отказ до LLM для неподдерживаемого файла.
2. **Инвентаризация:** построить перечень частей, абзацев, runs, секций, таблиц, изображений, формул, полей и ссылок. Сохранить map для последующего объяснения наблюдений.
3. **Разрешение оформления:** вычислить эффективные свойства с учётом docDefaults, цепочки styles/basedOn, paragraph/character styles, темы, numbering и direct formatting. Сохранить и исходные ссылки, и вычисленные значения; наследование не выдавать за явное локальное правило.
4. **Кандидаты ролей:** эвристики по стилям, положению, размеру, длине, ключевым словам и соседям; LLM получает компактный контекст, подтверждает либо предлагает роли в допустимой схеме.
5. **Агрегация:** по роли собрать варианты параметров, частоты, evidence block IDs и исключения. Противоречия не схлопывать в среднее значение.
6. **Черновик:** правила с происхождением `observed`, `inferred` или `manual`; неизвестные значения остаются неизвестными. Построить список обязательных вопросов.
7. **Review:** редактор выбирает роли и правила. Проверить единицы, конфликты, ссылки на стили, полноту обязательных правил и поддерживаемость выбранного профиля.
8. **Утверждение:** транзакционно сохранить неизменяемую версию, compiled rules hash, источник и снимок решения редактора. Завершение extraction job означает готовность черновика, а не автоматическое утверждение шаблона.

Детали — [извлечение шаблона](template-extraction.md).

## Поток B: статья → оформленный DOCX

1. **Preflight:** повторить проверку DOCX; проверить доступ к статье/шаблону, статус approved, наличие согласия и бюджета. Зафиксировать версии на старте.
2. **Parse:** создать Document IR и пакетный снимок, fingerprint научного содержания и inventory всех поддерживаемых частей. Определить совместимость с целевым профилем.
3. **Classify:** эвристики + LLM назначают семантические роли блокам, не изменяя текст. Большие документы разбиваются по блокам; таблица или формула не разрывается посередине.
4. **Resolve:** обнаружить неизвестные роли, конфликт порядка, отсутствующий обязательный раздел и риск неподдерживаемого преобразования. При блокирующем вопросе сохранить review revision и перейти в `needs_review`.
5. **Plan:** скомпилировать allowlisted операции: назначение стилей, абзацные свойства, параметры разделов, поддерживаемые свойства таблиц и изображений. Каждая операция содержит target IDs, before fingerprint и rule ID. Перестановки требуют отдельного явного разрешения.
6. **Transform:** копировать исходный пакет, внести минимальные разрешённые изменения, обновить relationships и content types только при необходимости, сохранить неприкосновенные части. Не вставлять текст из образца.
7. **Validate:** проверить ZIP/OPC/XML, инварианты содержания, связи объектов, правила оформления и непроверенные визуальные ограничения. Результат проверки не определяется ответом LLM.
8. **Publish:** при отсутствии blockers сохранить immutable DOCX и отчёт; транзакционно прикрепить artifact IDs и сменить статус. При наличии blockers — `failed`, код `INTEGRITY_VIOLATION`, отчёт доступен, итоговый DOCX недоступен.

## Псевдокод worker

```text
claim(job_id, expected_state_version)
inputs = load_authorized_immutable_inputs(job_id)
for stage in stages(job.kind):
    assert_not_cancelled_or_deleted(job_id)
    if valid_checkpoint(stage, inputs): continue
    output = stage.execute(inputs, bounded_resources)
    persist_checkpoint(output, input_hashes, attempt_id)
    if output.requires_review:
        transition_to_review(output.questions)
        return
validate_publish_preconditions(job_id, latest_state_version)
commit_artifacts_and_terminal_state()
```

На resume загружаются решения строго для текущего review revision. Перед публикацией снова проверяются отмена, удаление и ownership: успешная работа worker не даёт права публиковать уже удалённый документ.

## Выходы и происхождение

Каждый запуск сохраняет source hash, template version/hash, parser/renderer/validator versions, prompt version, provider/model ID, ответы классификатора, решения пользователя, план и report. Секреты и chain-of-thought не сохраняются. Достаточно структурированного результата и краткого обоснования с evidence IDs. Публичный отчёт не содержит служебного prompt целиком.
