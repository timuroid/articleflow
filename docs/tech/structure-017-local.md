# Восстановленная структурная сборка Web 017

**Обновление 019:** актуальное поведение описано в [recovery-019](recovery-019.md): effective typography, модельный контур, ввод пропусков, новые версии и реальный font audit. Ниже сохранено описание исходного ограниченного среза 017/018.

Статус: новая локальная реализация по [контракту](../product/structure-017.md), не побайтовое восстановление исчезнувшего релиза. Исходник: `src/articleflow/structure017.py`.

## Вход и выход

`inventory(path)` проверяет DOCX пакетом `docx_engine`, допускает одну секцию и верхнеуровневые абзацы/таблицы. Исключение для `bookmarkEnd` разрешено лишь непосредственно после абзаца с соответствующим `bookmarkStart`; оба узла затем перемещаются вместе. Комментарии, поля, другой story-текст, несколько секций и неизвестные верхнеуровневые узлы блокируют обработку кодом review. Каждый блок получает ID, индекс, тип и SHA-256 XML.

`suggest_roles` распознаёт только явные подписи частей русской аннотации, УДК, ключевые слова и несколько верхних эвристик. Он не является универсальным семантическим парсером. Переопределения пользователя проверяются по ID и разрешённым ролям. В локальном режиме все роли должны быть подтверждены перед статусом `ready`; без этого выдаётся `draft`.

`compile_document` группирует целые исходные OOXML-узлы по слотам, сохраняя их текст, таблицы, формулы, изображения и ссылки в пакете. Редакторская строка выводится отдельно в `editorial.docx`; она не становится автором статьи. До записи результата сравниваются мультимножества исходного текста и объектов по статье вместе с редакторским файлом. Сборщик не генерирует научные факты. Для отсутствующих обязательных слотов он вставляет заметный `[ЗАПОЛНИТЬ: role]` в позиции слота и оставляет статус `draft`.

Шаблон в `inspect_templates` содержит измеренные свойства абзацев/фрагментов из 1–10 DOCX, ключи вариантов и конфликты. При утверждении пользователь выбирает вариант для каждой роли; версия неизменяема для уже созданного пакета. Применяется только безопасное подмножество свойств (`spacing`, `ind`, `jc`, размер и семейство шрифта и пр.), а не всё наследование Word. Поэтому совпадение с эталоном по пикселям и перенос на другой издательский шаблон **не заявляются**. Для `ready` требуется точный audit Arial и Times New Roman на машине сервиса.

Проверены: синтетический HTTP-контур и настоящий пользовательский DOCX по зафиксированному SHA-256. Последний используется только как приватный локальный тест и не входит в Git. Проверки сохраняют содержимое узлов; визуальная редакторская экспертиза и независимый корпус остаются обязательными для заявления точности.

[Серия 018](../research/evaluation-018.md) измерила сохранность 7/7, но точное
оформление 0/6 и полную разметку ролей 0/7. Для качества нужны effective styles,
геометрия шаблона и отдельная типографика ролей. Общий `write_package` теперь
записывает части, чья DEFLATE-степень сжатия превышает 100:1, как ZIP_STORED.
Повторная загрузка результата проходит прежний защитный лимит; содержимое,
схема БД и API не меняются. Старые выходные файлы автоматически не исправляются.
