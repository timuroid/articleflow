# Развёртывание ArticleFlow на собственном сервере

## Состояние исходников

На 17 октября 2026 года публичная ветка `main` репозитория `timuroid/articleflow` содержит исследовательский CLI версии 0.7. В ней **нет** веб-сервера `src/articleflow/web017.py`, веб-ресурсов `src/articleflow/web_static017/` и установщиков `scripts/install-web017.sh`, `scripts/enable-https017.sh`. Клонирование одной только этой ветки не развернёт веб-приложение. Следующий исполнитель должен сначала получить исходники Web 017 или приватный установочный архив от владельца. Разработанный в отдельной рабочей среде архив не был опубликован в GitHub; его наличие у следующего исполнителя нужно проверить, а не предполагать.

Целевой домен, адрес сервера, имя SSH-пользователя и порт передаются исполнителю владельцем вне публичного Git. Проверить DNS и HTTPS на фактическом адресе. Нельзя объявлять развёртывание завершённым по одному DNS-ответу.

Ниже приведён порядок для **локального Web 017 на одном сервере**, если соответствующий приватный релиз доступен. Это не развёртывание описанной в [архитектуре](architecture.md) будущей системы React/Celery/PostgreSQL. Web 017 использует FastAPI, SQLite, локальные файлы, один процесс и отдельный reverse proxy. Массовые задания идут последовательно; поддержка нескольких пользователей и отказоустойчивая распределённая очередь пока не подтверждены.

## Что потребуется вне публичного Git

- Приватный архив релиза Web 017 либо проверенный checkout, в котором действительно есть перечисленные выше файлы, вместе с его SHA-256 от владельца. Архив может содержать реальные эталонные DOCX, рукопись и закрытый рабочий prompt: **не публиковать его в открытом репозитории**.
- Доступ к серверу через SSH владельца или консоль хостинга. Параметры подключения и пароль/ключ SSH передаются исполнителю отдельно и не вставляются в репозиторий или логи.
- При включении внешнего LLM — действующий ключ OpenRouter, закрытый prompt, **существующий** журнал расходов и подтверждённый актуальный лимит. Не обнулять журнал. Веб-приложение можно сначала запустить в локальном режиме без LLM.
- Если требуется точное Arial/Times New Roman — правомерно полученные файлы этих шрифтов. Одна установка Liberation не подтверждает совпадение гарнитур.

Ключ, ранее попавший в переписку или изображение, следует перевыпустить у провайдера до рабочего запуска. Не копировать секрет из истории в публичный файл. Образцы научных статей и пользовательские документы тоже не отправлять в Git.

## 1. Проверить релиз до доступа к серверу

В распакованном архиве или checkout должны существовать:

```text
pyproject.toml
src/articleflow/web017.py
src/articleflow/structure017.py
src/articleflow/web_static017/index.html
scripts/install-web017.sh
scripts/enable-https017.sh
```

Если этих файлов нет, **остановиться**: перед вами CLI 0.7 или неполный архив. Получить правильный релиз у владельца либо сначала реализовать и проверить веб-срез по продуктовой и технической документации. Не выдавать исследовательский CLI за веб-приложение. Перед передачей архива сверить его SHA-256 с хешем, полученным от владельца по отдельному каналу, и просмотреть список файлов: исключить API-ключи, SSH-данные, внутренние логи и лишние документы. В репозитории есть нераспаковывающий архив [аудитор](../../scripts/audit_web_release.py): `python scripts/audit_web_release.py /путь/articleflow-web-017.tar.gz --sha256 ОЖИДАЕМЫЙ_ХЕШ`. Он проверяет структуру и разделяет число потенциально публичных и закрытых файлов, но **не разрешает публикацию автоматически**: содержимое кандидатов всё равно требуется прочитать.

## 2. Осмотреть сервер без изменения настроек

Подключиться по SSH с параметрами, полученными отдельно, и проверить ОС, свободное место, действующий web stack и занятость портов:

```bash
ssh -p "$SSH_PORT" "$DEPLOY_USER@$SERVER_HOST"
cat /etc/os-release
df -h
free -h
ss -ltnp
systemctl status nginx --no-pager
systemctl status caddy --no-pager
```

Последние два `status` могут сообщить, что сервис отсутствует. Инсталлятор рассчитан на Ubuntu/Debian с systemd и nginx. Если порты 80/443 уже обслуживает иной сайт/proxy, интегрировать новый виртуальный хост в существующую конфигурацию после её резервного копирования: **не запускать инсталлятор поверх неё вслепую**. Он намеренно останавливается при конфликте. Не выключать чужие сайты или firewall без проверки их назначения. При ограниченном диске сначала определить размер распакованного релиза и пользовательских документов.

## 3. Передать и установить приватный релиз

На компьютере, где находится проверенный архив:

```bash
scp -P "$SSH_PORT" articleflow-web-017.tar.gz "$DEPLOY_USER@$SERVER_HOST:~/"
```

На сервере после проверки SHA-256 и списка содержимого архива:

```bash
sha256sum ~/articleflow-web-017.tar.gz
mkdir -p ~/articleflow-deploy
cd ~/articleflow-deploy
tar -tzf ~/articleflow-web-017.tar.gz | head -40
tar -xzf ~/articleflow-web-017.tar.gz
cd articleflow-web-017
test -f src/articleflow/web017.py
test -f scripts/install-web017.sh
sudo bash scripts/install-web017.sh
```

Ожидаемый формат архива — корневая папка `articleflow-web-017/`. Если он иной, сначала выяснить фактическую структуру, а не подставлять случайный путь. Скрипт должен создать отдельного непривилегированного пользователя, virtualenv, systemd-сервис и каталог данных; перед исполнением прочитать сам скрипт и проверить, что он не затронет чужую конфигурацию. Пароль для входа в приложение создаётся отдельно и не равен SSH-паролю; точный путь закрытого файла со сгенерированным паролем указан в проверенном инсталляторе.

До выдачи сертификата HTTP может отдавать только ACME challenge и служебный ответ. После успешного запуска backend и проверки конфигурации nginx:

```bash
systemctl status articleflow --no-pager
nginx -t
sudo bash scripts/enable-https017.sh
nginx -t
systemctl status articleflow --no-pager
```

Скрипт HTTPS предназначен для выпуска сертификата через certbot с webroot и настройки Basic Auth на всём сайте. Если на сервере уже есть TLS termination или иной reverse proxy, адаптировать конфигурацию к существующему стеку, сохранив приватный backend на `127.0.0.1`. Не отключать проверку TLS/SSH host key ради прохождения команды.

## 4. Настроить LLM и шрифты при необходимости

Встроенный режим без платных вызовов полезен для первичной проверки установки, но не доказывает автоматическое определение всех смысловых блоков. Для OpenRouter закрытые файлы должны находиться вне Git и читаться только пользователем сервиса. В Web 017 путь к закрытому JSON-конфигу передаётся через `ARTICLEFLOW_LLM_CONFIG` в приватных настройках сервиса. Сам конфиг указывает модель, путь к ключу, prompt, существующему usage ledger, лимит, цены и максимальное число токенов. Проверить актуальную цену до первого вызова. Перезапуск сервиса после настройки: `sudo systemctl restart articleflow`. Не записывать ключ в systemd unit, nginx, браузер или URL.

Для точного оформления шрифтов проверить реальные установленные семейства и font audit итогового DOCX. Если Arial/Times New Roman замещены, результат остаётся черновиком. Файлы шрифтов копировать только при наличии права их использовать на этом сервере.

## 5. Приёмка

1. `systemctl is-active articleflow` возвращает `active`, `nginx -t` проходит, HTTPS открывается с действительным сертификатом.
2. Запрос без логина к `https://<домен-приложения>/` получает `401`; после входа открывается UI. Не публиковать backend напрямую на внешнем интерфейсе.
3. Загрузить один разрешённый тестовый DOCX, увидеть job, сформировать результат и скачать DOCX/отчёт. Проверить, что незаполненные обязательные поля не выдаются как готовый документ.
4. Загрузить несколько документов, получить ZIP и сверить manifest с числом исходников и результатами каждого job. Проверить возобновление UI после перезагрузки страницы.
5. Проверить audit шрифтов. Если включена модель — отдельно выполнить один ограниченный вызов с явным согласием на передачу текста и проверить реальный расход по существующему ledger. Успех HTTP или валидный JSON сам по себе не доказывает правильность смысла.
6. Зафиксировать дату, commit/release hash, версии ОС/ПО, результат этих проверок и ограничения. Только после этого считать сервис развёрнутым.

Если инсталлятор обнаружил конфликт портов или неизвестный proxy, завершить без замены чужой конфигурации. Для обновлений сначала сделать согласованную резервную копию SQLite и каталога файлов. Путь указателя на предыдущий релиз определять по проверенному инсталлятору; переключение активного релиза и перезапуск сервиса выполнять лишь после проверки этого пути. Секреты, личные документы, каталог данных и пароль Basic Auth не должны попасть в резервную копию, доступную публично.
