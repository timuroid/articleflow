# Восстановление 019: структура, оформление и модельный контур

Статус: новая реализация поверх Web 017, а не байтовая копия утраченного архива. Старый CLI 0.7 сохранён. Результаты и ограничения — в [отчёте 019](../research/evaluation-019.md).

## Изменения сборщика

`typography019` вычисляет свойства через docDefaults, basedOn, стиль абзаца, стиль символа, прямое оформление и Latin theme fonts. Toggle-свойства учитываются при наследовании. Переносимая схема `web-019` хранит свойства и provenance наблюдений, без цитат научного текста и привязок к позиции эталона. Отдельные контексты: заголовки уровней, подписи, таблицы, иллюстрации, части аннотации, пустые разделители. `__base__` задаёт оформление по умолчанию, `__document__` — геометрию страницы. Схема `web-017` продолжает читаться старым ограниченным обработчиком; старые версии шаблонов автоматически не переизвлекаются.

Сохраняются текст, числа, индексы, ссылки, изображения, формулы, связи, нумерация и объединения ячеек. Локальные выделения основного текста сохраняются отдельно от типографики роли. Правило оформления подписи аннотации применяется к точному диапазону, в том числе внутри одного простого run. Порядок свойств OOXML нормализуется по типу элемента.

`fragments019` делит только простые абзацы аннотации с несколькими явными русскими подписями. Диапазоны полностью покрывают исходный текст, без переписывания. ID вида `n-NNNNNN:start:end` означает полуоткрытый символьный диапазон исходного абзаца. Поля, bookmarks, формулы, гиперссылки и рисунки внутри такого абзаца не разрезаются. Неподписанная свободная аннотация не получает выдуманную семантику: требуется решение редактора.

Проверка scientific payload допускает изменение свойств оформления и границ текстовых runs; сравнивает упорядоченное содержание внутри блока и мультимножество блоков после разрешённого переноса. Числа и связи защищены. Старая raw-XML метрика 018 сохранена отдельно: изменение оформления таблицы, ссылки и styles.xml теперь намеренно делает её false.

Ограничения: один основной story и одна секция; сложные поля и другие stories проходят прежние review gates. Условные table styles требуют проверки. Произвольные колонтитулы, сложная типографика таблиц и универсальная схема всех издателей не считаются проверенными. Пиксельное совпадение определено только для зафиксированного renderer, DPI и шрифтов.

## Модели и бюджет

`ARTICLEFLOW_MODEL_CONFIG` указывает на закрытый JSON с абсолютными путями `key_file`, `prompt`, `ledger`, а также `model`, необязательными `reasoning_effort`, `extractor_model`, `extractor_reasoning_effort`. Сам JSON, ключ и prompt в Git не входят. Рабочий выбор серии: GPT-6.1 Sol/low для эталонов, GPT-6 Luna/none для статьи; Qwen3.8-27B/none — измеренный альтернативный кандидат. Это выбор по малому development-набору, не доказательство минимального размера модели.

Модель возвращает только роли и контексты существующих блоков. Проверяются точная полнота, уникальность и порядок IDs, допустимые значения и совместимость роли с контекстом. Один вызов на документ; repair, retry и fallback отсутствуют. Отказ сохраняется как ошибка. Неподписанный фрагмент, который модель хочет вынести в редакторские заметки, требует подтверждения.

Перед каждым вызовом читаются доступный остаток, накопленный usage и текущие цены. Ledger блокируется `flock` на время резервирования и вызова. Резерв считается консервативно по байтовой длине запроса, запасу входа и максимуму выхода с учётом ценовых overrides. Условие: `max(учтённые расходы+неопределённые резервы, usage-baseline)+новый резерв <= cap`; отдельно проверяется доступный баланс. Неопределённый usage не превращается в ноль. Atomic write, fsync и права 0600 защищают запись попытки до отправки. Ключ передаётся curl через stdin, не argv/логи.

Исторический per-call ledger не найден. Новый checkpoint сохраняет накопленный provider usage, дополнительный cap 3 USD и признак утраты старой детализации. Это продолжение от фактического баланса, не обнуление расходов. После переноса в production **единственный активный ledger находится на сервере**. Локальная копия получает `read_only: true`; её использование завершается `LEDGER_READ_ONLY`. Для будущих локальных экспериментов нужно использовать тот же контролирующий контур или явно мигрировать его обратно, сохранив все записи.

## HTTP, версии и интерфейс

API-префикс сохранён `/api/v017`, поскольку существующие маршруты совместимы.

- `POST templates/{id}/analyze`, JSON `consent_external: true`: модель анализирует каждый эталон; создаётся новая неутверждённая версия. Старые версии остаются неизменными. При отказе провайдера новая версия не публикуется, расходы и приватный ответ сохраняются.
- `POST templates/{id}/approve`: дополнительно принимает `required` — список обязательных слотов. Интерфейс показывает понятные названия и варианты с источниками.
- `POST batches`: опциональные form-поля `use_llm=true`, `consent_external=true`. Без обоих модель не вызывается. По умолчанию остаётся локальный режим.
- `GET batches`: последние 50 пакетов с датой, шаблоном и числом файлов; результаты доступны после перезагрузки UI.
- `PATCH jobs/{id}/decisions`: `expected_revision`, `assignments`, необязательный `supplied`. Пользовательские сведения добавляются только в отсутствующие обязательные слоты, не заменяют исходный текст. Повторная сборка не вызывает LLM.
- ZIP под общей блокировкой сохраняет manifest и `reports/` для всех заданий, `results/` только для ready. Черновики скачиваются отдельно.

Миграция SQLite аддитивная: `batches.use_llm INTEGER DEFAULT 0`, `jobs.supplied_json TEXT DEFAULT '{}'`. Источники, старые версии, ревизии и статусы сохраняются. Откат к старому коду допустим, но он не понимает новые профили; резервную копию БД и файлов следует сохранять до обновления.

## Renderer и установка шрифтов

`fonts019.audit` создаёт DOCX-пробу с латиницей/кириллицей и четырьмя начертаниями, рендерит через LibreOffice и проверяет реальные имена шрифтов в PDF. Одного `fc-match` недостаточно: локальный bundled LibreOffice первоначально использовал Liberation при наличии Microsoft fonts в каталоге ОС.

`ARTICLEFLOW_FONTCONFIG` задаёт отдельный Fontconfig-файл для renderer; `ARTICLEFLOW_SOFFICE` — путь к headless executable. На macOS используется bundled LibreOffice, не открытое пользовательское приложение. На Ubuntu установлен пакет `libreoffice-writer`; Microsoft Core Fonts устанавливаются официальным дистрибутивным пакетом после согласия владельца с EULA. Не копировать лицензированные macOS fonts на сервер автоматически. Для каждого шаблона проверяются его реальные требуемые семейства; например, отсутствие Calibri оставляет результат draft даже при наличии Arial/TNR.

Производственный релиз, HTTPS, smoke-тест и резервные копии фиксируются отдельным [наблюдением развёртывания](deployment-observation-019.md).
