# Правила контекста и сохранение индексов 0.6

Требования: PRD-005, PRD-006, PRD-007, PRD-013, PRD-015. Цель — дополнить каталог условиями выбора и отдельно проверить DOCX-вход с сохранением научных индексов. Прежняя серия 0.5 остаётся неизменной; применение новых правил к сохранённому ответу — offline replay, не новый model trial.

## Подготовка шаблона

Из размеченного образца извлекаются наблюдения `условия → style ID`. Допустимые условия: смысловая роль, роли предыдущего/следующего блока, наличие текста/формул/рисунков, типы содержимого таблицы, число ячеек строки и положение ячейки first/middle/last/only. Номер абзаца статьи, block ID, текст, имена авторов, цитаты и смещения не могут быть условиями.

Если у роли единственный paragraph variant, достаточно условия role. Иначе используется структурный контекст. Если одинаковым условиям в образце соответствуют разные стили, правило **не создаётся**. Конфликт записывается отдельно, а runtime оставляет выбор модели с явным `needs_review`. Наиболее частый вариант автоматически не подставляется.

Layout-правила различают таблицу данных и сетку рисунков по ролям содержимого. У рисунка правило выбирает размер и run style по роли и контейнеру. Это фиксированные layout presets образца, не восстановление размеров по intrinsic image ratio: исходный документ может содержать растянутые изображения.

У каждого правила есть support count и статус наблюдения. Совпадение на обучающем образце не означает независимую проверку. Однократные наблюдения и все правила этого этапа имеют статус research draft. Runtime-пакет не содержит назначений по block IDs и текста образца; training audit хранится приватно отдельно.

## Применение

Сначала модель или сохранённый модельный ответ задаёт роли и варианты в формате 0.5. Правила получают именно предсказанные роли. При совпадении условий выбирается правило с наибольшим количеством проверенных полей. Равноприоритетные противоречащие правила дают отказ. Изменения записываются с rule ID; пробелы покрытия и неоднозначность не объявляются успехом.

Неизвестная структура не наследует ближайший рисунок/таблицу. Для нескольких допустимых вариантов требуется совпавшее правило либо review. Runtime не читает source oracle, исходный образец или golden PDF.

## Научные индексы: отдельный входной протокол

При чтении входного DOCX извлекаются только диапазоны `superscript`/`subscript` и неявный baseline для остального текста. Sidecar связан с content hash, содержит длины блоков и точные code-point диапазоны; paragraph styles, шрифтов, размеров и координат страницы в нём нет. Модельный выбор не может стереть или добавить индексы поверх этого payload.

Это явно объявленное сохранение разметки входного DOCX, **не реконструкция индексов из чистого текста**. Оно оценивается как I2-подобный структурированный вход с opaque OMML; результаты не заменяют I1 или 0.5. Обычные bold/italic пока остаются результатом модели и правил шаблона.

Для каждого character style заранее выводятся три варианта, отличающиеся только `vertAlign`. Расширенный каталог строится независимо от текста и конкретных диапазонов статьи. На сборке spans разделяются по границам защищённых индексов; полный scientific payload проверяется после renderer.

## Приёмка этапа

Нужны синтетические проверки смены текста/IDs, конфликтов условий, неизвестной структуры, подмены hash и сохранения индексов. Затем — абляции на сохранённых планах: только правила, только индексы, оба изменения. Успех payload, выбора вариантов и exact pixels публикуются раздельно. Если остаётся заведомая неоднозначность правил и exact gate не проходит offline, новые платные повторы не нужны для подтверждения того же ограничения.

## Команды

```bash
articleflow fit-context-rules artifacts/catalogue-004/template/rules.json artifacts/catalogue-004/content/content.json artifacts/catalogue-004/oracle-plan.json artifacts/context-rules.json
articleflow extract-indices private-fixtures/input.docx artifacts/catalogue-004/content/content.json artifacts/source-indices.json
articleflow apply-context-rules artifacts/catalogue-004/template artifacts/catalogue-004/content artifacts/model-compiled-plan.json artifacts/context-result --rules artifacts/context-rules.json --indices artifacts/source-indices.json
articleflow render-catalogue artifacts/context-result/template artifacts/catalogue-004/content artifacts/context-result/plan.json artifacts/context-candidate.docx
```

Первая команда относится только к подготовке шаблона. В runtime используется входная статья и уже готовый RulePack; source oracle не передаётся. Flags `--rules` и `--indices` независимы для абляций. Выходная папка преобразования должна быть пустой. `changes.json` фиксирует rule IDs, изменения и unresolved targets. Новые character variants не меняют исходный шаблон на месте.
