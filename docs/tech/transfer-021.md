# Полнота шаблона и визуальная проверка 021

PRD-005, PRD-007, PRD-023–026; SC-088–089. Причина изменения: пользователь
обнаружил неверный выступ библиографии, пропавшее отдельное оформление
ключевых слов и вертикальный интервал перед заголовком. Счётчик 328/328
свойств серии 020 сравнивал результат с неполным профилем и не обнаруживал
ошибки самого извлечения. [Новые измерения](../research/evaluation-021.md).

## Извлечение и применение

- Resolver читает уровень `numbering.xml`, override и наследуемый `numPr`.
  Переносимый `numbering-021` хранит форму `%1.`, suffix, выравнивание,
  отступы, tabs и свойства символа номера. Чужие numId не переносятся.
- Номер использует свойства знака абзаца эталона. Их пропуск давал 11 pt
  при правильных 12 pt у текста записи.
- Простая библиография с буквальным `N. ` преобразуется в нумерацию Word.
  Создаются собственные идентификаторы и startOverride для каждого
  исходного номера: пропуски и номера 9/10/100 сохраняются. Это фиксирует
  связь с цитированием; вставка новой записи редактором не обеспечивает
  автоматическую сквозную перенумерацию ссылок в тексте.
- Преобразование выполняется после обычного аудита сохранности. Обратная
  подстановка исходного префикса и numPr должна дать ту же научную сигнатуру.
  Неоднозначные двойные номера, ведущие нули, сложные текстовые префиксы и
  неподдерживаемая нумерация сохраняются с вопросом, результат остаётся draft.
- Inline-подпись ключевых слов делится на два абзаца, если утверждённый
  профиль содержит `keywords.heading` и `keywords`. Разрешён простой текст
  без объектов/ссылок/закладок; точные диапазоны сохраняют исходные символы.
  Уже разделённый блок не дублируется. При вводе пользователем недостающего
  списка добавляется только утверждённая служебная подпись из эталона. Пустота или один заголовок не считаются
  заполненными ключевыми словами.
- Пустые абзацы непосредственно перед заголовком входят в его
  `leading_spacing`. Сохраняются размер знака абзаца и интервалы. Существующие
  пустые строки используются повторно; недостающие добавляются как оформление
  с provenance. Более трёх строк и избыток исходных строк требуют проверки.
- Отсутствующая в целевом профиле docGrid удаляется; иначе в результат
  просачивалась сетка исходного DOCX. Табуляция в `pPr/tabs` больше не
  принимается за символ текста; настоящая табуляция `r/tab` сохраняется.

## Полнота и вопросы

Извлечение сохраняет наблюдённые роли. Ключевые слова, если они наблюдались,
предлагаются обязательными. Отсутствующие обязательные данные дают
заполнитель. Отсутствие наблюдённого, но не обязательного блока тоже
попадает в `coverage` и вопросы: оно не исчезает из отчёта. Список литературы
проверяется отдельно. Наблюдение по одной статье не делает финансирование
или чужие сведения об авторах обязательными и не разрешает их копирование.

В отчёт добавлены `coverage` и `representation_changes`. Исправленные
числовые метки, разделённая подпись и пустые строки оформления перечислены
по исходным block IDs. Слоты и план LLM не менялись.

## Визуальная обратная связь

При утверждении нового шаблона с `leading_spacing` запускается
`templatecheck021.validate_samples`: для выбранного варианта строятся
контрольные документы с одинаковым синтетическим текстом. Один использует
исходный OOXML эталона, другой — извлечённый профиль. Проверяются расстояние
между блоками (диагностика в pt), число/размер страниц и точное совпадение
пикселей. Дополнительный вариант без отступа служит отрицательным контролем.
Эталон используется только оценщиком, не передаётся runtime-сборщику новой
статьи и не отправляется внешней модели.

`POST /api/v017/templates/{id}/approve` возвращает HTTP 409 с
`TEMPLATE_LAYOUT_MISMATCH` при несовпадении или
`TEMPLATE_LAYOUT_CHECK_UNAVAILABLE`, если renderer недоступен. Утверждённая
версия при этом не создаётся. Успешная версия хранит `layout_validation`.
Без применимых интервалов статус проверки `not_applicable`, а не passed.
CLI использует тот же код:

```bash
python scripts/verify_template_layout021.py \
  --reference private-fixtures/reference.docx \
  --spec artifacts/transfer021/spec.json \
  --profile artifacts/transfer021/profile.json \
  --output artifacts/transfer021/new-visual-check
```

Вопросы пользователю нужны для неоднозначной нормы или недостающих фактов.
Техническое несовпадение является ошибкой извлечения/сборки и не должно
предлагаться как выбор пользователю. Автоматическая генерация новых
семантических гипотез и повторные LLM repairs пока не реализованы.

## Границы и миграция

Поля аддитивны к typography-019; старые утверждённые версии не изменяются.
Нужно заново извлечь и утвердить шаблон, чтобы получить нумерацию и интервалы.
Старый профиль библиографии без правила нумерации явно требует проверки.
Python `required=None` использует прежние основные слоты и наблюдаемые
ключевые слова; явный список сохраняет выбор вызывающего кода.

Проверка рендером сейчас охватывает границы заголовков. Она не доказывает
полноту требований журнала, английской части, сносок, многоуровневых списков
или всех таблиц. Полный автоматический цикл извлечения произвольного шаблона
остаётся задачей развития. Рендер требует configured LibreOffice и шрифтов;
проверка выполняется локально и не тратит LLM-бюджет.

Канонического технического PDF у проекта нет; DOCX/PDF рукописи проверяются
отдельно. Изменения 020/021 на production в этой итерации не устанавливались.
